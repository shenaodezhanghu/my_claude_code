# 第零章 环境搭建与百炼接入

这一章，我们先解决两个基础问题：让 Python 能够调用阿里云百炼，以及确认模型 ID、API Key、Base URL 三者正确匹配。只有先建立稳定的模型调用，后面的工具调用和 Agent Loop 才有可靠基础。

## 0.1 本章目标

完成本章后，你将能够：

<strong>（1）理解百炼 API 的三个必要配置</strong>：API Key、Base URL 和模型 ID。

<strong>（2）避免 Windows CMD 环境变量中的引号陷阱</strong>。

<strong>（3）用 Python 完成第一次真实模型调用</strong>。

<strong>（4）建立后续章节使用的练习项目</strong>。

## 0.2 先修复当前的 404

你执行的是：

```bat
set MINI_CLAUDE_MODEL="Qwen3.7-Plus"
```

在 Windows CMD 中，这种写法会把双引号也保存进变量。错误响应已经显示服务端收到的是：

```text
`"Qwen3.7-Plus"`
```

正确写法是把变量名和值整体放在引号中：

```bat
set "MINI_CLAUDE_MODEL=qwen-plus"
```

注意，百炼控制台显示的产品名称不一定等于 API 模型 ID。模型 ID 必须使用控制台或模型文档给出的准确值，不能自行把 `qwen` 改成 `Qwen`，也不能自行添加 `3.7`。

可以先查看变量是否正确：

```bat
echo [%MINI_CLAUDE_MODEL%]
```

正确结果中不应包含双引号：

```text
[qwen-plus]
```

### 0.2.1 展示名称不等于模型 ID

百炼控制台可能同时出现产品名称、系列名称和 API 模型 ID。程序真正发送的是 API 模型 ID，例如：

```text
展示名称：Qwen Plus
模型 ID：qwen-plus
```

模型 ID 必须与控制台给出的值完全一致。大小写、引号、空格或自行添加的版本号都可能导致 `model_not_found`。

### 0.2.2 CMD、PowerShell 和 PyCharm 的环境变量不同

Windows CMD：

```bat
set "MINI_CLAUDE_MODEL=qwen-plus"
```

PowerShell：

```powershell
$env:MINI_CLAUDE_MODEL="qwen-plus"
```

PyCharm 的绿色运行按钮不会自动读取你后来在外部 CMD 中设置的临时变量。使用 PyCharm 时，应在 Run Configuration 中配置环境变量，或者使用 `.env` 并在代码中调用 `load_dotenv()`。

## 0.3 配置百炼

本教程使用百炼的 OpenAI 兼容协议。在 CMD 中设置：

```bat
set "OPENAI_API_KEY=你的百炼API-Key"
set "OPENAI_BASE_URL=你的百炼OpenAI兼容Base-URL"
set "MINI_CLAUDE_MODEL=qwen-plus"
```

如果你的 Key 以 `sk-sp-` 开头，它属于 Token Plan 或 Coding Plan，必须使用该套餐专用的 Base URL，不能与普通百炼地址混用。

三个配置必须属于同一套服务：

```text
API Key
  + Base URL
  + 模型 ID
  = 一次有效请求
```

只要其中一项来自其他地域、业务空间或套餐，就可能出现 401、403 或 404。

## 0.5 实现模型客户端

创建 `mini_claude/model.py`：

```python
import os

from openai import OpenAI


def create_client() -> OpenAI:
    api_key = os.environ.get("OPENAI_API_KEY")
    base_url = os.environ.get("OPENAI_BASE_URL")

    if not api_key:
        raise RuntimeError("缺少 OPENAI_API_KEY")
    if not base_url:
        raise RuntimeError("缺少 OPENAI_BASE_URL")

    return OpenAI(api_key=api_key, base_url=base_url)


def get_models() -> str:
    return os.environ.get("MINI_CLAUDE_MODEL", "qwen-plus").strip('"\'')
```

`create_client()` 只负责连接哪个服务，`get_models()` 只负责选择哪个模型。这里沿用你当前代码中的函数名；把两项职责分开后，替换模型时不需要修改 Agent Loop。

在入口文件最前面加载 `.env`：

```python
from dotenv import load_dotenv

load_dotenv()
```

项目根目录中的 `.env` 示例：

```env
OPENAI_API_KEY=你的百炼API-Key
OPENAI_BASE_URL=你的百炼OpenAI兼容地址
MINI_CLAUDE_MODEL=qwen-plus
```

同时创建 `.gitignore`：

```gitignore
.env
.venv/
__pycache__/
.idea/
```

这里的 `strip` 是额外防护，但不应依赖它掩盖错误配置。正确做法仍然是在 CMD 中使用 `set "变量=值"`。

创建 `main.py`：

```python
from mini_claude.model import create_client, get_models


client = create_client()
response = client.chat.completions.create(
    model=get_models(),
    messages=[
        {"role": "user", "content": "只回复：连接成功"},
    ],
)

print(response.choices[0].message.content)
```

## 0.6 运行与验证

```bat
python main.py
```

预期输出：

```text
连接成功
```

如果仍然出现 `model_not_found`，依次检查：

1. `echo [%MINI_CLAUDE_MODEL%]` 是否带引号。
2. 模型 ID 是否来自百炼控制台，而不是产品展示名称。
3. API Key 与 Base URL 是否属于同一套餐和地域。
4. API Key 所属业务空间是否有模型权限。

在继续第一章之前，还应验证 PyCharm 实际运行的文件和工作目录：

```python
from pathlib import Path

print("当前文件：", __file__)
print("工作目录：", Path.cwd())
```

后续 `read_file("demo.txt")` 使用的是工作目录，而不是 `agent.py` 所在目录。因此 PyCharm 的 Working directory 应设置为：

```text
E:\研究生\学习\ai_study\claude-code\claude-code-from-scratch\myclaude\mycode
```

PyCharm 的项目解释器也必须选择安装了依赖的同一个环境，例如：

```text
C:\Users\86151\.conda\envs\claude-code\python.exe
```

解释器不同会导致找不到 `openai`、`python-dotenv` 或 `tavily-python`；工作目录不同则会让 `mini_claude` 导入和工具的项目根目录与终端运行结果不一致。

## 0.8 本章小结

本章完成的是“普通 LLM 调用”，它还不是 Agent。Agent 与普通聊天程序的关键区别是：模型能够决定何时调用工具，程序能够执行工具，并把结果送回模型继续推理。下一章将实现这个核心循环。
