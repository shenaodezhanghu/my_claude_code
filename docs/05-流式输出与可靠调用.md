# 第五章 为百炼 Agent 增加流式输出与可靠调用

> 当前代码进度：`MINI_CLUE_AGENT.chat()` 仍使用非流式 `chat.completions.create()`。本章是下一步教程，不代表当前代码已经实现。

第四章解决了持续对话和会话保存，但模型生成期间终端没有反馈。本章使用百炼的 OpenAI 兼容流式协议，让文本边生成边显示，同时正确拼接被拆成多个 chunk 的工具调用。

原教程同时讨论 Anthropic 与 OpenAI 两种后端。你的项目目前只使用百炼 OpenAI 兼容接口，因此本章只实现这一条真实需要的路径，不引入未使用的 Anthropic SDK。

## 5.1 本章目标

1. 理解普通响应和流式响应的区别。
2. 累积 `delta.content` 并实时显示。
3. 按 `index` 重建分片到达的 `tool_calls`。
4. 流结束后生成与现有 Agent Loop兼容的 assistant 字典。
5. 为 429、503 和网络抖动增加有限重试。
6. 保持 `ToolRegistry`、`ToolContext` 和消息协议不变。

## 5.2 数据流

```text
chat(user_text)
  ↓
_call_model_stream()
  ├── delta.content → 立即打印并累积
  └── delta.tool_calls → 按 index 累积 id/name/arguments
  ↓
组装 assistant_message
  ↓
写入 self.messages
  ↓
有 tool_calls？
  ├── 否 → 返回完整文本
  └── 是 → Registry 执行 → 继续 Agent Loop
```

流式输出只改变“如何取得模型回复”，不改变工具执行和消息回传协议。

## 5.3 创建流式结果类型

在 `mini_claude/agent.py` 顶部增加：

```python
from dataclasses import dataclass


@dataclass
class StreamResult:
    message: dict
    finish_reason: str
```

使用普通字典保存最终 assistant 消息，是为了继续兼容会话 JSON 保存。

## 5.4 拼接百炼流式响应

在 `MINI_CLUE_AGENT` 中增加：

```python
def _call_model_stream(self) -> StreamResult:
    stream = self.client.chat.completions.create(
        model=self.model,
        messages=[
            {"role": "system", "content": build_system_prompt()},
            *self.messages,
        ],
        tools=self.tools.schemas(),
        stream=True,
    )

    content_parts: list[str] = []
    tool_calls: dict[int, dict] = {}
    finish_reason = "stop"

    for chunk in stream:
        if not chunk.choices:
            continue

        choice = chunk.choices[0]
        delta = choice.delta

        if delta.content:
            print(delta.content, end="", flush=True)
            content_parts.append(delta.content)

        if delta.tool_calls:
            for part in delta.tool_calls:
                current = tool_calls.setdefault(
                    part.index,
                    {"id": "", "name": "", "arguments": ""},
                )
                if part.id:
                    current["id"] = part.id
                if part.function and part.function.name:
                    current["name"] += part.function.name
                if part.function and part.function.arguments:
                    current["arguments"] += part.function.arguments

        if choice.finish_reason:
            finish_reason = choice.finish_reason

    content = "".join(content_parts)
    assembled_calls = [
        {
            "id": item["id"],
            "type": "function",
            "function": {
                "name": item["name"],
                "arguments": item["arguments"],
            },
        }
        for _, item in sorted(tool_calls.items())
    ]

    message: dict = {
        "role": "assistant",
        "content": content or None,
    }
    if assembled_calls:
        message["tool_calls"] = assembled_calls

    if content:
        print()

    return StreamResult(message=message, finish_reason=finish_reason)
```

工具参数不能在每个 chunk 到达时立即 `json.loads()`，因为某一片可能只有半个 JSON 字符串。必须在流结束、参数拼接完整后再解析。

## 5.5 接入现有 Agent Loop

把原来的非流式请求和 SDK `message` 处理替换为：

```python
result = self._call_model_stream()
message = result.message
self.messages.append(message)

tool_calls = message.get("tool_calls") or []
if not tool_calls:
    return str(message.get("content") or "")

for tool_call in tool_calls:
    name = tool_call["function"]["name"]
    try:
        arguments = json.loads(tool_call["function"]["arguments"])
    except json.JSONDecodeError as exc:
        tool_result = f"Error: invalid tool arguments: {exc}"
    else:
        print(f"-> {name}: {arguments}")
        tool_result = self.tools.execute(
            name,
            arguments,
            self.tool_context,
        )

    self.messages.append(
        {
            "role": "tool",
            "tool_call_id": tool_call["id"],
            "content": tool_result,
        }
    )
```

流式版本已经直接把 assistant 消息构造成普通字典，不再调用 `message.model_dump()`。

## 5.6 增加有限重试

创建 `mini_claude/retry.py`：

```python
import random
import time
from collections.abc import Callable
from typing import TypeVar


T = TypeVar("T")


def is_retryable(error: Exception) -> bool:
    status = getattr(error, "status_code", None)
    if status in {429, 500, 502, 503, 504}:
        return True
    text = str(error).lower()
    return "timeout" in text or "connection reset" in text


def with_retry(operation: Callable[[], T], max_retries: int = 3) -> T:
    for attempt in range(max_retries + 1):
        try:
            return operation()
        except Exception as exc:
            if attempt >= max_retries or not is_retryable(exc):
                raise
            delay = min(2**attempt, 30) + random.random()
            print(f"模型请求失败，{delay:.1f} 秒后重试：{exc}")
            time.sleep(delay)

    raise RuntimeError("unreachable")
```

然后：

```python
result = with_retry(self._call_model_stream)
```

不要重试参数错误、鉴权失败和 `model_not_found`。这些错误重复发送不会自行恢复。

流已经输出一部分文本后再自动重试可能造成重复显示。教学版先接受这一限制；以后可以在“收到第一个 chunk 之前”重试，开始输出后则直接报错。

## 5.9 理解检查

1. 为什么流式工具参数必须按 `part.index` 累积后才能执行 `json.loads()`？
   因为流式工具如果不适用这个参数，可能会导致工具使用的先后顺序颠倒，比如1、洗碗和2、洗澡，1的洗和2的澡合在一起后会导致先后顺序颠倒
2. 一次模型回复包含多个工具调用时，怎样保证各自的 ID、名称和参数不会串在一起？
   模型返回会包含part.index，按照index区分
3. 为什么终端显示由流式函数负责，而 `chat()` 仍然要返回完整文本？
   返回完整文本是为了给程序拿最终结果，比如后续保存记录什么的
4. 哪些错误适合重试，参数错误和权限拒绝为什么不应自动重试？
   网络错误适合重试，参数错误说明工具使用错了，继续重试也没有意义还是会错。权限拒绝也是
5. 平滑逐字符打印为什么可能降低整体吞吐速度？
   逐字符打印看起来更平滑，但增加了大量终端 I/O 和 flush 次数，因此整体吞吐会下降。
