# 第六章 为工具调用增加权限与安全控制

> 当前代码进度：工具拥有项目路径限制和 read-before-edit，但还没有统一权限门。本章代码尚未接入当前 Agent。

路径限制只能阻止文件工具逃出项目目录，不能阻止危险 Shell、意外覆盖或未经确认的修改。权限检查必须位于 Agent Loop 和 `ToolRegistry.execute()` 之间，确保被拒绝的动作根本不会执行。

## 6.1 本章目标

1. 区分工具输入验证、项目沙箱和用户授权。
2. 建立 `allow / deny / confirm` 三种权限结果。
3. 对读工具默认放行，对编辑和危险命令进行控制。
4. 把拒绝结果返回模型，让它调整方案。
5. 支持 `default`、`accept_edits` 和 `dont_ask` 三种最小模式。

## 6.2 权限层次

```text
模型生成 tool_call
  ↓
check_permission(name, arguments, mode)
  ├── allow   → Registry.execute()
  ├── deny    → 不执行，返回拒绝结果
  └── confirm → 询问用户
                  ├── y → 执行
                  └── n → 返回拒绝结果
```

`resolve_project_path()` 仍然保留。权限系统不是路径校验的替代品，而是它外面的另一层保护。

## 6.3 定义权限结果

创建 `mini_claude/permissions.py`：

```python
from dataclasses import dataclass
from typing import Literal


PermissionAction = Literal["allow", "deny", "confirm"]


@dataclass(frozen=True)
class PermissionResult:
    action: PermissionAction
    message: str = ""
```

## 6.4 危险命令检查

```python
import re


DANGEROUS_COMMANDS = (
    r"\brm\s+-rf\b",
    r"\bdel\s+/[sq]\b",
    r"\brmdir\s+/s\b",
    r"\bgit\s+reset\s+--hard\b",
    r"\bgit\s+push\b.*\s--force\b",
    r"\bformat\s+[a-z]:",
    r"\bshutdown\b",
)


def is_dangerous_command(command: str) -> bool:
    return any(
        re.search(pattern, command, flags=re.IGNORECASE)
        for pattern in DANGEROUS_COMMANDS
    )
```

正则只能作为教学版的基础防线，无法完整理解 Shell 的变量展开、子命令和管道。复杂或无法判断的命令应倾向确认，而不是宣称安全。

## 6.5 实现最小权限策略

继续在 `permissions.py` 中增加：

```python
READ_ONLY_TOOLS = {
    "read_file",
    "list_files",
    "grep_search",
    "web_fetch",
    "web_search",
    "environment_info",
}

EDIT_TOOLS = {"write_file", "edit_file"}


def check_permission(
    tool_name: str,
    arguments: dict,
    mode: str = "default",
) -> PermissionResult:
    if tool_name in READ_ONLY_TOOLS:
        return PermissionResult("allow")

    if mode == "dont_ask" and tool_name in EDIT_TOOLS:
        return PermissionResult("deny", "非交互模式禁止修改文件")

    if tool_name == "run_shell":
        command = str(arguments.get("command", ""))
        if is_dangerous_command(command):
            if mode == "dont_ask":
                return PermissionResult("deny", f"危险命令：{command}")
            return PermissionResult("confirm", command)
        return PermissionResult("allow")

    if tool_name in EDIT_TOOLS:
        if mode == "accept_edits":
            return PermissionResult("allow")
        return PermissionResult(
            "confirm",
            f"{tool_name}: {arguments.get('path', '')}",
        )

    return PermissionResult("confirm", f"未知权限工具：{tool_name}")
```

未知工具默认确认，比默认允许更稳妥。

## 6.6 接入 MINI_CLUE_AGENT

构造函数增加：

```python
def __init__(self, permission_mode: str = "default") -> None:
    # 保留原有初始化
    self.permission_mode = permission_mode
    self.confirmed_actions: set[str] = set()
```

增加确认方法：

```python
def _confirm(self, message: str) -> bool:
    try:
        answer = input(f"\n允许执行 {message!r}？[y/N] ").strip().lower()
    except (EOFError, KeyboardInterrupt):
        return False
    return answer in {"y", "yes"}
```

在 `self.tools.execute()` 之前加入：

```python
permission = check_permission(
    name,
    arguments,
    self.permission_mode,
)

if permission.action == "deny":
    tool_result = f"Action denied: {permission.message}"
elif permission.action == "confirm":
    key = f"{name}:{permission.message}"
    allowed = key in self.confirmed_actions or self._confirm(permission.message)
    if allowed:
        self.confirmed_actions.add(key)
        tool_result = self.tools.execute(name, arguments, self.tool_context)
    else:
        tool_result = "User denied this action."
else:
    tool_result = self.tools.execute(name, arguments, self.tool_context)
```

拒绝不是 Python 异常。它应该作为正常 `role="tool"` 结果返回模型，这样模型可以选择只解释、换用安全工具或请求用户调整目标。

## 6.7 CLI 权限模式

在 `parse_args()` 中增加：

```python
parser.add_argument(
    "--permission-mode",
    choices=["default", "accept_edits", "dont_ask"],
    default="default",
)
```

创建 Agent：

```python
agent = MINI_CLUE_AGENT(permission_mode=args.permission_mode)
```

行为对照：

| 模式 | 读工具 | 编辑工具 | 普通 Shell | 危险 Shell |
|---|---|---|---|---|
| `default` | 允许 | 确认 | 允许 | 确认 |
| `accept_edits` | 允许 | 允许 | 允许 | 确认 |
| `dont_ask` | 允许 | 拒绝 | 允许 | 拒绝 |

本章不添加 `--yolo`。完全绕过权限风险较高，学习阶段没有必要。

## 6.8 与现有工具保护的关系

执行一次编辑会依次经过：

```text
权限门：用户是否允许编辑？
  ↓
路径限制：目标是否在 project_root 内？
  ↓
read-before-edit：是否读过最新版本？
  ↓
mtime：读取后是否被外部修改？
  ↓
真正写入
```

任何一层失败都不应继续执行。

## 6.11 理解检查

1. 为什么权限判断必须发生在 `ToolRegistry.execute()` 之前？
   如果在工具调用之后判断权限，可能会导致文件已经更改或者这个工具已经执行，就没有意义
2. 为什么用户拒绝后仍要给模型追加一条匹配 `tool_call_id` 的结果？
   因为用户拒绝也是工具调用结果
3. Registry 与权限层为什么必须保持职责分离？
   Registry 管“能力”，权限层管“边界”。
4. 为什么不能只让模型判断 Shell 命令是否危险？
   因为模型可能会进入到其他文件夹执行写什么的操作，他也可能认为他的操作不是危险的
5. 对正则无法可靠分析的复杂命令，fail-closed 应该返回 `deny` 还是 `confirm`？分别适合什么运行模式？
   普通交互模式：
   unknown → confirm
   严格只读 / Plan Mode：
   unknown → deny
