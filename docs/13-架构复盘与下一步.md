# 第十三章 补全 Mini-Claude 完整架构

> 本章只对齐原版 `claude-code-from-scratch` 的完整 mini-claude 架构，不尝试实现生产级 Claude Code。Claude Code 独有或明显超出 mini-claude 教学目标的 Hooks、Coordinator、Swarm、LSP、Bash AST 和企业级策略不属于本章。

## 13.1 本章目标

前十二章采用“先建立最小可运行版本，再逐步增加能力”的方式实现 Coding Agent。为了让每一章都容易理解，有些原版 mini-claude 已经具备的能力被明确推迟。

本章要完成两件事：

1. 比较“当前项目”和“原版完整 mini-claude”，准确找出尚未对齐的部分。
2. 按依赖顺序补全前十二章推迟的能力，使项目形成完整 mini-claude，而不是继续扩展 Claude Code 的生产级外围能力。

第十五章的 `/goal`、`/loop` 和 Auto Mode 暂不实现，也不计入本章完成标准。

## 13.2 范围边界

### 本章需要补全

- static/dynamic System Prompt 真正分离。
- 百炼显式 `cache_control` 与缓存用量统计。
- Deferred Tools 与 `tool_search`。
- 独立工具并行执行。
- 后端允许时的 streaming 工具早期启动接口。
- Token/轮次/费用预算。
- 四层上下文管理。
- 会话工作区、working memory、长期 Memory 工具化与按需检索。
- Skill 元数据、inline/fork 和多来源发现。
- 完整 Plan 文件、进入/退出工具与审批流程。
- 内置和自定义 Sub-Agent 类型。
- 多 MCP Server 管理。
- CLI 模型参数、每会话工作区、外部目录动态授权、任务取消和完整状态保存。
- 工具执行统计、diff 输出和验收测试。

### 本章不实现

- Claude Code 的 Hooks 平台。
- Coordinator 与 Swarm。
- LSP Client。
- Shell AST 与真正系统沙箱。
- 企业级身份、审计和策略源。
- 第十五章的自治与续跑。
- 为了使用框架而引入 LangGraph。

这些能力不是“遗漏”，而是另一个阶段的目标。

## 13.6 static/dynamic Prompt 与缓存

### 本节新增/优化功能及作用

| 新增或优化功能 | 作用 |
|---|---|
| `ModelCapabilities` | 统一描述当前模型是否支持显式缓存、流式工具完成事件和流式 usage，避免把不同模型的能力写死在 Agent 中。 |
| `PromptParts(static, dynamic)` | 把长期不变的规则与每轮变化的目录、Git、Mode、Memory 等信息分开，为缓存和后续上下文治理建立稳定边界。 |
| `build_system_message()` | 根据模型能力选择普通字符串消息或带 `cache_control` 的结构化消息。 |
| 显式 Prompt Cache | 缓存稳定的 System Prompt，减少重复输入成本和首 Token 等待时间；不支持时自动退回普通请求。 |
| 缓存 usage 统计 | 区分普通输入 Token 与缓存命中 Token，验证缓存是否真正产生收益。 |

> **从本节开始统一使用增量修改。** 每一步只改当前功能涉及的代码。下面出现的“最终状态代码”只用于完成步骤后核对，不能直接覆盖整个文件；否则会提前带入后续功能，并覆盖你已经写好的内容。

### 13.6.1 为什么不能只改函数注解

当前 `build_system_prompt()` 返回一个字符串，`agent.py` 随后继续使用 `+=` 追加 Mode 和 Memory：

```python
system_prompt = build_system_prompt()
system_prompt += self._mode_prompt()
system_prompt += recall_memories(...)
```

因此，不能只把返回类型改成 `PromptParts`。必须同时完成三处替换：

1. `model.py` 定义当前模型是否启用显式缓存。
2. `prompt.py` 返回结构化的 static 和 dynamic。
3. `agent.py` 不再对 Prompt 对象使用 `+=`，而是先补齐 dynamic，再构造 System Message。

```python
from __future__ import annotations

from dataclasses import dataclass
import os

from openai import OpenAI


TRUE_VALUES = {"1", "true", "yes", "on"}


@dataclass(frozen=True)
class ModelCapabilities:
    explicit_cache: bool
    tool_stream_completion: bool
    usage_in_stream: bool


def create_client(
    api_key: str | None = None,
    base_url: str | None = None,

        raise RuntimeError("缺少 OPENAI_API_KEY")
    if not resolved_base:
        raise RuntimeError("缺少 OPENAI_BASE_URL")

    return OpenAI(

def get_model(override: str | None = None) -> str:
```

### 13.6.3 第二步：在现有 `prompt.py` 中增加结构化结果

不要删除现有 `STATIC_PROMPT`、`get_git_context()` 和 `find_project_instruction()`。

接下来只替换原来的 `build_system_prompt()` 这个函数，不替换整个文件。新函数为：

```python
def build_prompt_parts(
    project_root: Path,
    mode_prompt: str = "",
    memory_prompt: str = "",
    deferred_names: Iterable[str] = (),
) -> PromptParts:
    instruction_path = find_project_instruction(project_root)
    sections = [
        "当前环境：",
        f"- 操作系统：{platform.system()}",
        f"- 当前工作目录：{project_root}",
        "",
        "Git 信息：",
        get_git_context(),
    ]

    if instruction_path:
        try:
            instruction = instruction_path.read_text(
                encoding="utf-8"
            ).strip()
        except OSError:
            instruction = ""
        if instruction:
            sections.extend(["", "项目说明：", instruction])

    if mode_prompt.strip():
        sections.extend(["", mode_prompt.strip()])
    if memory_prompt.strip():
        sections.extend(["", memory_prompt.strip()])

    names = sorted(set(deferred_names))
    if names:
        sections.extend(
            [
                "",
                "可按需加载的工具：" + ", ".join(names),
                "需要时先调用 tool_search。",
            ]
        )

    return PromptParts(
        static=STATIC_PROMPT.strip(),
        dynamic="\n".join(sections).strip(),
    )
```

再在它下面新增 `build_system_message()`：

```python
def build_system_message(
    parts: PromptParts,
    capabilities: ModelCapabilities,
) -> dict:
    if not capabilities.explicit_cache:
        return {
            "role": "system",
            "content": f"{parts.static}\n\n{parts.dynamic}",
        }
    return {
        "role": "system",
        "content": [
            {
                "type": "text",
                "text": parts.static,
                "cache_control": {"type": "ephemeral"},
            },
            {"type": "text", "text": parts.dynamic},
        ],
    }
```


这里已经完整解决了原实现中的两个问题：

- Git 信息不再只有找到项目说明文件时才加入。
- `find_project_instruction()` 返回路径，`read_project_instruction()` 专门读取内容，职责不再混淆。

## 13.7 Deferred Tools 与 `tool_search`

### 本节新增/优化功能及作用

| 新增或优化功能 | 作用 |
|---|---|
| Tool 的 `deferred` 元数据 | 标记哪些工具不需要在每次模型请求中发送完整 Schema。 |
| Registry 的 active/deferred 状态 | 分离当前可见工具和可按需激活工具，同时继续由同一个 Registry 管理执行。 |
| `tool_search` | 让模型根据任务搜索并激活延迟工具，而不是把所有工具定义永久塞进上下文。 |
| dynamic Prompt 中的延迟工具摘要 | 告诉模型还有哪些能力可以搜索，但只发送短名称和说明。 |
| 激活状态持久化到当前会话 | 工具激活后在后续轮次继续可用，避免模型重复搜索同一个工具。 |

> 本节继续采用增量修改。先给 Tool 增加一个元数据字段，再扩展 Registry，最后新建 `tool_search`。不要提前修改 Sub-Agent 回调、Plan Mode 或 Session。

### 13.7.1 第一步：只给 `Tool` 增加 deferred 元数据

打开 `tools/base.py`，在现有：

```python
read_only = False
concurrency_safe = False
```

下面新增一行：

```python
deferred = False
```

本步骤不要修改 `ToolContext.subagent_runner` 的参数，它属于 13.13。下面的整段代码只作为最终状态核对：

```python
from __future__ import annotations

from abc import ABC, abstractmethod
from collections.abc import Callable
from dataclasses import dataclass, field
from pathlib import Path
from typing import Any


@dataclass
class ToolContext:
    """一次 Agent 会话中由所有工具共享的运行状态。"""

    project_root: Path
    read_file_state: dict[str, float] = field(default_factory=dict)
    subagent_runner: Callable[[str, str], str] | None = None


class Tool(ABC):
    read_only = False
    concurrency_safe = False
    deferred = False

    def __init__(self, name: str, description: str) -> None:
        self.name = name
        self.description = description

    @abstractmethod
    def parameters(self) -> dict[str, Any]:
        raise NotImplementedError

    @abstractmethod
    def run(self, args: dict, context: ToolContext) -> str:
        raise NotImplementedError

    def schema(self) -> dict[str, Any]:
        return {
            "type": "function",
            "function": {
                "name": self.name,
                "description": self.description,
                "parameters": self.parameters(),
            },
        }
```

最终状态中的 `subagent_runner` 会在 13.13 改成 `(task, agent_type)`；现在仍保持原来的 `Callable[[str], str]`，保证完成 13.7 后项目立刻可以运行。

### 13.7.2 第二步：逐项扩展 `tools/registry.py`

上一小节只给 `Tool` 增加了 `deferred` 标记，但 Registry 还不会使用它。如果现在直接把某个工具写成：

```python
deferred = True
```

它仍然会被 `schemas()` 全量发送给模型，也仍然能被 `execute()` 直接执行。因此，这一小节要让 Registry 真正管理延迟工具的生命周期。

#### 13.7.2.1 先理解 Registry 中的两个集合

延迟加载不等于“工具尚未注册”。所有工具仍然在程序启动时注册，以便 Registry 知道它们的名称、说明和执行对象；区别只在于是否把完整 Schema 暴露给模型。

```text
_tools
└── 保存全部已注册工具
    ├── 普通常驻工具：注册后立即可见
    └── deferred 工具：注册后暂时隐藏

_activated
└── 只保存已经被激活的 deferred 工具名称
```

状态变化是：

```text
注册 deferred 工具
→ 工具存在于 _tools，但 Schema 不发送给模型
→ tool_search 根据名称和描述找到工具
→ activate() 把名称加入 _activated
→ 下一次 schemas() 开始返回该工具的完整 Schema
→ 模型随后可以正常调用
```

因此不需要把工具对象从一个 Registry 搬到另一个 Registry，也不需要重新实例化工具。

#### 13.7.2.2 清理 Registry 不再负责的旧代码

打开 `tools/registry.py`，删除顶部已经注释掉的 `MAX_RESULT_CHARS` 和旧 `truncate_result()`。

#### 13.7.2.3 增加激活状态

在 `__init__()` 现有：

```python
self._tools: dict[str, Tool] = {}
```

下面增加：

```python
self._activated: set[str] = set()
```

这里使用 `set`，因为：

- 同一个工具重复激活不会产生重复项；
- 判断名称是否已经激活是快速的成员检查；
- Session 只需要保存工具名称，不需要序列化 Tool 对象。

此时还没有改变 Schema，程序应该继续按原方式运行。

#### 13.7.2.4 增加全部工具查询与可见性判断

在 `get()` 后先增加：

```python
def all_tools(self) -> list[Tool]:
    return list(self._tools.values())
```

`all_tools()` 给 Registry 内部管理、测试和以后统计使用。它返回全部工具，包括尚未激活的 deferred 工具；不要把它直接传给模型。

然后增加：

```python
def is_active(self, name: str) -> bool:
    tool = self.get(name)
    if tool is None:
        return False
    return not tool.deferred or name in self._activated
```

判断顺序分别表示：

1. 工具不存在：不可用；
2. 工具不是 deferred：注册后一直可用；
3. 工具是 deferred：只有名称进入 `_activated` 后才可用。

把这个规则集中到一个函数中很重要。后面的 Schema 导出和执行检查都调用它，避免两处对“已激活”的理解不一致。

#### 13.7.2.5 让 `schemas()` 只暴露当前可见工具

原来的 `schemas()`：

```python
def schemas(self) -> list[dict]:
    return [tool.schema() for tool in self._tools.values()]
```

替换为：

```python
def schemas(self) -> list[dict]:
    return [
        tool.schema()
        for tool in self._tools.values()
        if self.is_active(tool.name)
    ]
```

这一步才真正减少发送给模型的工具 Schema。注意，工具仍然存在于 `_tools`，只是当前请求的 `tools=` 参数中看不到它。

为什么不能从 `_tools` 删除 deferred 工具？因为下一节的 `tool_search` 还要搜索它的名称和描述，激活后也要复用同一个对象执行。

#### 13.7.2.6 列出尚未激活的延迟工具

在 `schemas()` 后增加：

```python

        tool.name
        for tool in self._tools.values()
        if tool.deferred and tool.name not in self._activated
```

这个函数只返回短名称，不返回完整 Schema。13.6 的 dynamic Prompt 会使用它生成类似：

#### 13.7.2.7 增加搜索逻辑

接着增加：

```python
def search(self, query: str) -> list[Tool]:
    terms = [
        term.lower()
        for term in query.split()
        if term.strip()
    ]
    candidates = [
        tool
        for tool in self._tools.values()
        if tool.deferred and tool.name not in self._activated
    ]
    if not terms:
        return candidates

    matches: list[Tool] = []
    for tool in candidates:
        haystack = f"{tool.name} {tool.description}".lower()
        if all(term in haystack for term in terms):
            matches.append(tool)
    return matches
```

搜索分三步：

1. 把查询拆成小写关键词；
2. 候选集只包含“尚未激活的 deferred 工具”；
3. 在工具名称和说明中匹配所有关键词。

第一版不需要向量数据库或额外模型调用。工具说明本来就应该准确描述能力，简单文本匹配足以验证 deferred tools 的完整流程。以后工具数量真正变大时，再替换搜索算法，`ToolSearchTool` 的调用方式不需要变化。

空查询返回全部候选工具，是为了支持“列出还有哪些延迟工具”。

#### 13.7.2.8 增加激活逻辑

继续增加：

```python
def activate(self, names: list[str]) -> list[Tool]:
    activated: list[Tool] = []
    for name in names:
        tool = self.get(name)
        if tool is None or not tool.deferred:
            continue
        self._activated.add(name)
        activated.append(tool)
    return activated
```

这里同时完成两件事：

- 把合法 deferred 工具名称加入 `_activated`；
- 返回对应 Tool 对象，让下一节可以把名称、说明和 Schema 告诉模型。

未知名称和普通常驻工具会被忽略，因为普通工具不需要激活。`set.add()` 具有幂等性，同一名称重复激活不会破坏状态。

为什么激活后不立即重新请求模型？Registry 只管理状态，不负责模型调用。`tool_search` 的结果会先回填到消息历史，主 Agent Loop 自然进入下一轮；下一轮调用 `schemas()` 时，新工具才会出现在模型请求中。

#### 13.7.2.9 增加 Session 保存与恢复接口

增加读取当前状态的方法：

```python
def activated_names(self) -> list[str]:
    return sorted(self._activated)
```

它用于把激活状态保存进 Session。仍然使用排序，保证 Session 文件稳定、便于比较。

再增加恢复方法：

```python
def restore_activated(self, names: list[str]) -> None:
    valid = {
        name
        for name in names
        if (tool := self.get(name)) is not None and tool.deferred
    }
    self._activated = valid
```

恢复时不能直接执行：

```python

```

旧 Session 可能包含已经删除、改名或不再 deferred 的工具。`restore_activated()` 只保留当前 Registry 中仍然合法的 deferred 工具，避免损坏状态进入运行时。

本节先建立接口，真正把 `activated_names()` 写入 Session 属于 13.15。不要在这里提前重写 `session.py`。

#### 13.7.2.10 给 `execute()` 增加最后一道可见性检查

`schemas()` 隐藏工具只能阻止模型正常看到它，并不是执行权限边界。旧消息、手工构造的 tool call 或错误代码仍可能直接调用：

```python
self.tools.execute("web_search", arguments, context)
```

因此，在 `execute()` 判断完工具存在之后、进入 `try` 之前增加：

```python
if not self.is_active(name):
    return (
        f"Error: deferred tool {name!r} 尚未激活，"
        "请先使用 tool_search"
    )
```

最终顺序必须是：

```text
检查工具是否存在
→ 检查 deferred 工具是否激活
→ 执行 Tool.run()
→ 统一处理异常和字符串结果
```

这属于纵深防御：Schema 可见性负责“模型能看到什么”，`execute()` 检查负责“程序实际允许执行什么”。

#### 13.7.2.12 最终状态核对

所有功能已经按上面的顺序逐项加入。现在再使用下面代码核对方法位置和最终结构；不要跳过前面的步骤直接整体覆盖文件：

```python
from __future__ import annotations

from .base import Tool, ToolContext


class ToolRegistry:
    """统一管理工具、延迟激活、Schema 导出和调用分发。"""

    def __init__(self) -> None:
        self._tools: dict[str, Tool] = {}
        self._activated: set[str] = set()

    def register(self, tool: Tool) -> None:
        if tool.name in self._tools:
            raise ValueError(f"工具已经注册：{tool.name}")
        self._tools[tool.name] = tool

    def get(self, name: str) -> Tool | None:
        return self._tools.get(name)

    def all_tools(self) -> list[Tool]:
        return list(self._tools.values())

    def is_active(self, name: str) -> bool:
        tool = self.get(name)
        if tool is None:
            return False
        return not tool.deferred or name in self._activated

    def schemas(self) -> list[dict]:
        return [
            tool.schema()
            for tool in self._tools.values()
            if self.is_active(tool.name)
        ]

    def deferred_names(self) -> list[str]:
        return sorted(
            tool.name
            for tool in self._tools.values()
            if tool.deferred and tool.name not in self._activated
        )

    def search(self, query: str) -> list[Tool]:
        terms = [
            term.lower()
            for term in query.split()
            if term.strip()
        ]
        candidates = [
            tool
            for tool in self._tools.values()
            if tool.deferred and tool.name not in self._activated
        ]
        if not terms:
            return candidates

        matches: list[Tool] = []
        for tool in candidates:
            haystack = f"{tool.name} {tool.description}".lower()
            if all(term in haystack for term in terms):
                matches.append(tool)
        return matches

    def activate(self, names: list[str]) -> list[Tool]:
        activated: list[Tool] = []
        for name in names:
            tool = self.get(name)
            if tool is None or not tool.deferred:
                continue
            self._activated.add(name)
            activated.append(tool)
        return activated

    def activated_names(self) -> list[str]:
        return sorted(self._activated)

    def restore_activated(self, names: list[str]) -> None:
        valid = {
            name
            for name in names
            if (tool := self.get(name)) is not None and tool.deferred
        }
        self._activated = valid

    def execute(
        self,
        name: str,
        arguments: dict,
        context: ToolContext,
    ) -> str:
        tool = self.get(name)
        if tool is None:
            return f"Error: unknown tool: {name}"
        if not self.is_active(name):
            return (
                f"Error: deferred tool {name!r} 尚未激活，"
                "请先使用 tool_search"
            )

        try:
            result = tool.run(arguments, context)
        except Exception as exc:
            result = f"Error: {type(exc).__name__}: {exc}"

        return result if isinstance(result, str) else str(result)
```

### 13.7.3 新建 `tools/search_tool.py`

```python
from __future__ import annotations

import json

from .base import Tool, ToolContext
from .registry import ToolRegistry


class ToolSearchTool(Tool):
    read_only = True
    concurrency_safe = True

    def __init__(self, registry: ToolRegistry) -> None:
        self.registry = registry
        super().__init__(
            "tool_search",
            "按名称或描述搜索尚未加载的延迟工具，并激活匹配工具。",
        )

    def parameters(self) -> dict:
        return {
            "type": "object",
            "properties": {
                "query": {
                    "type": "string",
                    "description": "工具名称或能力关键词；留空列出全部延迟工具",
                }
            },
            "required": ["query"],
            "additionalProperties": False,
        }

    def run(self, args: dict, context: ToolContext) -> str:
        query = str(args.get("query", "")).strip()
        matches = self.registry.search(query)
        activated = self.registry.activate(
            [tool.name for tool in matches]
        )
        if not activated:
            return "No matching deferred tools found."

        payload = [
            {
                "name": tool.name,
                "description": tool.description,
                "schema": tool.schema(),
            }
            for tool in activated
        ]
        return (
            "已激活以下工具；下一轮模型请求会包含它们的 Schema：\n"
            + json.dumps(payload, ensure_ascii=False, indent=2)
        )
```

### 13.7.7 为什么激活后要等下一轮

模型当前这一轮收到的工具 Schema 已经固定。`tool_search` 虽然能立刻修改 Registry，但不能反向修改已经发出的 API 请求。因此正确顺序是：

```text
本轮调用 tool_search
→ 工具结果告诉模型激活成功
→ Agent Loop 进入下一次 API 请求
→ self.tools.schemas() 重新读取 Registry
→ 新工具 Schema 出现在下一轮
```

不要让 `tool_search` 直接调用目标工具，否则会绕开模型参数生成和权限检查。

## 13.8 Streaming 与工具调度器

### 本节新增/优化功能及作用

| 新增或优化功能 | 作用 |
|---|---|
| 独立 `streaming.py` | 把流式文本和工具调用分片组装从 Agent Loop 中拆出，避免协议解析与业务流程混在一起。 |
| `ToolScheduler` | 统一处理工具的顺序、并行、权限结果和异常，使消息回填顺序保持确定。 |
| 只读工具并行执行 | 对不存在依赖关系的读取、搜索任务并发执行，缩短一次多工具调用的总耗时。 |
| 写工具顺序执行 | 防止多个写入相互覆盖，并继续遵守 read-before-edit、mtime 和权限检查。 |
| streaming 早期启动能力接口 | 在模型后端提供可靠“工具参数已完成”事件时允许提前执行；百炼不支持时安全等待完整流结束。 |
| `CancellationToken` | 让 CLI、预算或用户可以请求停止长时间模型和工具任务。 |

### 13.8.1 新建 `streaming.py`

当前 `_call_model_stream()` 同时承担四件事：

1. 遍历百炼返回的流式 chunk；
2. 立即显示文本；
3. 拼接被拆散的工具名称和 JSON 参数；
4. 构造最终 assistant message。

如果继续在 Agent 中增加 usage、其他模型后端和工具提前启动，协议解析会越来越难测试。因此先把“把流收集成一条完整消息”提取成纯粹的 `streaming.py`。这一小节只迁移解析逻辑，不修改 Agent Loop。

#### 13.8.1.1 先明确输入和输出

输入不是一条完整消息，而是一串 chunk：

```text
chunk 1：文本 "Hel"
chunk 2：文本 "lo"
chunk 3：tool_call[0] 名称 "read_"
chunk 4：tool_call[0] 名称 "file"
chunk 5：tool_call[0] 参数 "{\"path\":"
chunk 6：tool_call[0] 参数 "\"demo.txt\"}"
chunk 7：finish_reason="tool_calls"
chunk 8：只有 usage，没有 choices
```

输出需要重新变成标准 assistant message：

```python
{
    "role": "assistant",
    "content": "Hello",
    "tool_calls": [
        {
            "id": "call_1",
            "type": "function",
            "function": {
                "name": "read_file",
                "arguments": "{\"path\":\"demo.txt\"}",
            },
        }
    ],
}
```

注意：这里暂时保留 `arguments` 为 JSON 字符串。解析和权限检查仍然属于 Agent 的 `_prepare_tool_jobs()`，不能在协议收集器里提前执行工具。

#### 13.8.1.2 创建文件并加入最小导入

新建 `mini_claude/streaming.py`，先写：

```python
from __future__ import annotations

from dataclasses import dataclass
from typing import Any
```

这些类型分别表示：

- `Iterable[Any]`：OpenAI SDK 返回的可遍历流；
- `Callable[[str], None]`：收到文本时交给外部显示；
- `Any`：避免让本模块绑定某一个 SDK 版本的具体 chunk 类型。

#### 13.8.1.3 定义收集结果

增加：

```python
@dataclass(frozen=True)
class StreamResult:
    message: dict
    finish_reason: str
    usage: Any | None = None
```

三个字段分别解决：

- `message`：加入 `self.messages` 的标准消息；
- `finish_reason`：区分正常结束、工具调用、长度限制等停止原因；
- `usage`：交给后面的 `RunStats` 统计 Token 和缓存命中。

`StreamResult` 搬到这里后，13.8.3 才会删除 `agent.py` 中原来的同名类，不能现在先删，否则中间状态无法运行。

#### 13.8.1.5 初始化四类累积状态

```python
}
```

#### 13.8.1.6 先收集 usage，再判断 choices

写出循环的第一部分：

```python
for chunk in stream:
    if getattr(chunk, "usage", None) is not None:
        usage = chunk.usage

    choices = getattr(chunk, "choices", None) or []
    if not choices:
        continue
```

必须先读取 usage。开启：

```python
stream_options={"include_usage": True}
```

后，最后一个 chunk 可能只有 usage、没有 choices。如果先执行 `continue`，缓存 Token 和总 Token 会永远统计不到。

使用 `getattr()` 是为了让测试可以传入简单假对象，也能兼容 usage 不存在的后端。

#### 13.8.1.7 收集并立即转发文本

在取得 `choice` 和 `delta` 后增加：

```python
choice = choices[0]
delta = choice.delta

if delta.content:
    on_text(delta.content)
    content_parts.append(delta.content)
```

两条操作缺一不可：

- `on_text()` 负责让用户立即看到增量内容；
- `content_parts.append()` 负责最后构造能保存进 Session 的完整消息。

只显示不保存会导致恢复会话时丢失回答；只保存不回调则失去流式显示效果。

#### 13.8.1.8 按 index 拼接工具片段

继续增加：

```python
if delta.tool_calls:
    for part in delta.tool_calls:
        current = tool_calls.setdefault(
            part.index,
            {
                "id": "",
                "name": "",
                "arguments": "",
            },
        )
        if part.id:
            current["id"] = part.id
        if part.function and part.function.name:
            current["name"] += part.function.name
        if part.function and part.function.arguments:
            current["arguments"] += part.function.arguments
```

这里名称和参数都使用 `+=`，因为任意一个字段都可能被拆成多个 chunk。不能在看到一段可以被 `json.loads()` 解析的参数后立即执行；服务器仍可能继续追加片段。

`setdefault()` 保证第一次遇到索引时创建容器，后续片段继续写入同一个容器。

#### 13.8.1.9 保存最终停止原因

在每轮结尾增加：

```python
if choice.finish_reason:
    finish_reason = choice.finish_reason
```

中间 chunk 的 `finish_reason` 通常为空，只有结束 chunk 才提供真实值，所以只在非空时覆盖默认的 `stop`。

#### 13.8.1.10 把内部累积状态还原为消息

循环结束后先合并文本：

```python
content = "".join(content_parts)
```

再按 index 排序并恢复工具协议结构：

```python
assembled_calls = [
    {
        "id": item["id"],
        "type": "function",
        "function": {
            "name": item["name"],
            "arguments": item["arguments"],
        },
    }
    for _, item in sorted(tool_calls.items())
]
```

排序不是为了决定执行先后，而是恢复模型原始 tool call 顺序，确保后面 `tool_call_id` 与结果对应。

最后构造消息并返回：

```python
message: dict = {
    "role": "assistant",
    "content": content or None,
}
if assembled_calls:
    message["tool_calls"] = assembled_calls

return StreamResult(
    message=message,
    finish_reason=finish_reason,
    usage=usage,

```

无文本但存在工具调用时，`content` 使用 `None`，而不是空字符串，保持与 SDK 消息格式一致。

#### 13.8.1.11 最终状态核对

现在再用下面的完整代码核对文件结构。它只是前面十个小步骤组合后的结果，不要跳过步骤直接覆盖：

```python
from __future__ import annotations

from collections.abc import Callable, Iterable
from dataclasses import dataclass
from typing import Any


@dataclass(frozen=True)
class StreamResult:
    message: dict
    finish_reason: str
    usage: Any | None = None


def collect_openai_stream(
    stream: Iterable[Any],
    on_text: Callable[[str], None],
) -> StreamResult:
    content_parts: list[str] = []
    tool_calls: dict[int, dict[str, str]] = {}
    finish_reason = "stop"
    usage = None

    for chunk in stream:
        if getattr(chunk, "usage", None) is not None:
            usage = chunk.usage

        choices = getattr(chunk, "choices", None) or []
        if not choices:
            continue

        choice = choices[0]
        delta = choice.delta

        if delta.content:
            on_text(delta.content)
            content_parts.append(delta.content)

        if delta.tool_calls:
            for part in delta.tool_calls:
                current = tool_calls.setdefault(
                    part.index,
                    {
                        "id": "",
                        "name": "",
                        "arguments": "",
                    },
                )
                if part.id:
                    current["id"] = part.id
                if part.function and part.function.name:
                    current["name"] += part.function.name
                if part.function and part.function.arguments:
                    current["arguments"] += part.function.arguments

        if choice.finish_reason:
            finish_reason = choice.finish_reason

    content = "".join(content_parts)
    assembled_calls = [
        {
            "id": item["id"],
            "type": "function",
            "function": {
                "name": item["name"],
                "arguments": item["arguments"],
            },
        }
        for _, item in sorted(tool_calls.items())
    ]

    message: dict = {
        "role": "assistant",
        "content": content or None,
    }
    if assembled_calls:
        message["tool_calls"] = assembled_calls

    return StreamResult(
        message=message,
        finish_reason=finish_reason,
        usage=usage,
    )
```

这里没有定义一个永远不会产生的 `ToolCallReady`。百炼 OpenAI Chat Completions 只有增量片段和整段响应的最终结束原因，当前实现必须在流结束后才能确认完整参数。

### 13.8.2 新建完整 `scheduler.py`

当前 Agent 按模型返回顺序逐个执行工具，两个互不依赖的读取任务也只能等待前一个结束。最直接的想法是把全部工具一次性提交到线程池，但这会让后面的读取越过前面的编辑，看到错误的文件状态。

因此 Scheduler 的目标不是“全部并行”，而是：

```text
连续且 concurrency_safe 的工具组成一个并行批次
→ 遇到不安全工具，先等待前面的安全批次结束
→ 不安全工具单独顺序执行
→ 再开始收集下一个安全批次
→ 最后按照模型原顺序返回结果
```

#### 13.8.2.1 先定义调度器不负责什么

Scheduler 不负责：

- 解析工具 JSON 参数；
- 判断权限；
- 弹出用户确认；
- 查找 Tool 对象；
- 把结果追加进消息历史。

这些仍由 13.8.5～13.8.7 的 Agent 方法完成。Scheduler 只接收已经解析、已经通过权限检查的任务。

这样线程池永远不会在后台线程调用 `input()`，也不会绕过 PermissionManager。

#### 13.8.2.2 创建文件并加入导入

新建 `mini_claude/scheduler.py`：

```python
from __future__ import annotations

from collections.abc import Callable
from concurrent.futures import ThreadPoolExecutor, as_completed
from dataclasses import dataclass
import threading
```

`ThreadPoolExecutor` 适合这里的文件、网络和子进程等待型工具。当前步骤不使用 `asyncio`，避免同时重写现有同步 Tool 接口。

#### 13.8.2.3 定义输入任务 `ToolJob`

增加：

```python
@dataclass(frozen=True)
class ToolJob:
    index: int
    call_id: str
    name: str
    arguments: dict
    concurrency_safe: bool
```

字段作用：

- `index`：模型返回的原始顺序；
- `call_id`：后面生成 tool message 时与调用配对；
- `name/arguments`：实际执行信息；
- `concurrency_safe`：是否允许进入并行批次。

Scheduler 不应再次根据工具名称猜测安全性。`concurrency_safe` 来自 Tool 类的显式元数据，并由 Agent 创建任务时传入。

#### 13.8.2.4 定义统一输出 `ToolOutcome`

增加：

```python
@dataclass(frozen=True)
class ToolOutcome:
    index: int
    call_id: str
    content: str
```

无论成功、异常还是取消，每个输入 Job 最终都必须产生一个 Outcome。否则模型发出的 tool call 得不到对应 tool result，下一次 API 请求会违反工具消息协议。

#### 13.8.2.5 增加最大线程数

先写类和构造函数：

```python
class ToolScheduler:
    def __init__(self, max_workers: int = 4) -> None:
        self.max_workers = max(1, max_workers)
```

使用 `max(1, max_workers)` 防止错误配置为 0 导致线程池启动失败。线程越多不一定越快，第一版限制为 4，避免一次模型响应创建过多文件或网络任务。

#### 13.8.2.6 建立 `execute()` 的状态容器

增加函数边界：

```python
def execute(
    self,
    jobs: list[ToolJob],
    execute_one: Callable[[ToolJob], str],
    cancelled: threading.Event,
) -> list[ToolOutcome]:
```

然后初始化：

```python
outcomes: dict[int, ToolOutcome] = {}
safe_batch: list[ToolJob] = []
```

- `safe_batch` 保存当前连续安全任务；
- `outcomes` 按原始 index 保存结果，因为并行任务完成顺序不稳定。

`execute_one` 由 Agent 注入，Scheduler 因此不依赖 `ToolRegistry`，可以单独测试。

#### 13.8.2.7 先实现单个任务的可靠执行

在 `execute()` 内新增局部函数：

```python
def run_job(job: ToolJob) -> ToolOutcome:
    if cancelled.is_set():
        return ToolOutcome(
            index=job.index,
            call_id=job.call_id,
            content="Cancelled before tool execution.",
        )
    try:
        content = execute_one(job)
    except Exception as exc:
        content = f"Error: {type(exc).__name__}: {exc}"
    return ToolOutcome(
        index=job.index,
        call_id=job.call_id,
        content=content,
    )
```

取消检查放在真实执行前。它不能强制杀死已经进入 `Tool.run()` 的线程，因此长时间工具仍应自行支持超时；这里保证尚未开始的工具不再启动。

异常必须转成 Outcome，而不是让一个 Future 异常终止整个批次。模型需要看到工具失败信息，才能决定是否修正参数或换一种方案。

#### 13.8.2.8 实现安全批次刷新

继续在 `execute()` 内增加：

```python
def flush_safe_batch() -> None:
    if not safe_batch:
        return
```

没有待执行任务时直接返回。

只有一个任务时不创建线程池：

```python
if len(safe_batch) == 1:
    outcome = run_job(safe_batch[0])
    outcomes[outcome.index] = outcome
    safe_batch.clear()
    return
```

多个任务时才并发：

```python
workers = min(self.max_workers, len(safe_batch))
with ThreadPoolExecutor(max_workers=workers) as pool:
    futures = {
        pool.submit(run_job, job): job
        for job in safe_batch
    }
    for future in as_completed(futures):
        outcome = future.result()
        outcomes[outcome.index] = outcome
safe_batch.clear()
```

`as_completed()` 让先完成的任务先被收集，不会因列表第一个慢任务阻塞结果收集。但结果仍然按 `outcome.index` 保存，最终不会打乱消息顺序。

每次刷新后必须 `safe_batch.clear()`，否则同一个任务会在下一个批次重复执行。

#### 13.8.2.9 用不安全工具形成顺序屏障

增加主遍历：

```python
for job in jobs:
    if job.concurrency_safe:
        safe_batch.append(job)
        continue

    flush_safe_batch()
    outcome = run_job(job)
    outcomes[outcome.index] = outcome
```

遇到安全工具时先积累，不立即执行。遇到写工具或其他不安全工具时：

1. 等待前面的安全批次全部结束；
2. 当前不安全工具单独执行；
3. 后续安全工具进入新的批次。

这个不安全工具就是顺序屏障。例如：

```text
read A、read B、edit C、read D
```

绝不能把 `read D` 提前到 `edit C` 之前运行，因为它可能需要读取编辑后的内容。

#### 13.8.2.10 刷新尾部批次并恢复原顺序

循环结束后仍可能有一批安全工具没有遇到屏障，因此增加：

```python
flush_safe_batch()
```

最后返回：

```python
return [outcomes[index] for index in sorted(outcomes)]
```

线程完成顺序可能是 `2、0、1`，但模型工具协议仍要求结果与原 tool call 正确对应。按 index 排序后，Agent 才能稳定生成 tool messages。

#### 13.8.2.11 最终状态核对

下面是前面步骤组合后的完整 `scheduler.py`，只用于检查是否遗漏字段、清空批次或最终排序，不要直接跳过过程整体覆盖：

```python
from __future__ import annotations

from collections.abc import Callable
from concurrent.futures import ThreadPoolExecutor, as_completed
from dataclasses import dataclass
import threading


@dataclass(frozen=True)
class ToolJob:
    index: int
    call_id: str
    name: str
    arguments: dict
    concurrency_safe: bool


@dataclass(frozen=True)
class ToolOutcome:
    index: int
    call_id: str
    content: str


class ToolScheduler:
    def __init__(self, max_workers: int = 4) -> None:
        self.max_workers = max(1, max_workers)

    def execute(
        self,
        jobs: list[ToolJob],
        execute_one: Callable[[ToolJob], str],
        cancelled: threading.Event,
    ) -> list[ToolOutcome]:
        outcomes: dict[int, ToolOutcome] = {}
        safe_batch: list[ToolJob] = []

        def run_job(job: ToolJob) -> ToolOutcome:
            if cancelled.is_set():
                return ToolOutcome(
                    index=job.index,
                    call_id=job.call_id,
                    content="Cancelled before tool execution.",
                )
            try:
                content = execute_one(job)
            except Exception as exc:
                content = f"Error: {type(exc).__name__}: {exc}"
            return ToolOutcome(
                index=job.index,
                call_id=job.call_id,
                content=content,
            )

        def flush_safe_batch() -> None:
            if not safe_batch:
                return
            if len(safe_batch) == 1:
                outcome = run_job(safe_batch[0])
                outcomes[outcome.index] = outcome
                safe_batch.clear()
                return

            workers = min(self.max_workers, len(safe_batch))
            with ThreadPoolExecutor(max_workers=workers) as pool:
                futures = {
                    pool.submit(run_job, job): job
                    for job in safe_batch
                }
                for future in as_completed(futures):
                    outcome = future.result()
                    outcomes[outcome.index] = outcome
            safe_batch.clear()

        for job in jobs:
            if job.concurrency_safe:
                safe_batch.append(job)
                continue

            flush_safe_batch()
            outcome = run_job(job)
            outcomes[outcome.index] = outcome

        flush_safe_batch()
        return [outcomes[index] for index in sorted(outcomes)]
```

这个调度器只并行“连续出现的安全工具”。例如：

```text
read_file A
read_file B
edit_file C
read_file D
```

执行分组为：

```text
[read A, read B] 并行
→ edit C 顺序
→ read D
```

这样不会把后面的读取越过一次写入提前执行。

### 13.8.5 在 Agent 中增加权限准备方法

把 JSON 解析、权限确认和执行分开。新增：

```python
def _prepare_tool_jobs(
    self,
    tool_calls: list[dict],
) -> tuple[list[ToolJob], dict[int, str]]:
    jobs: list[ToolJob] = []
    immediate_results: dict[int, str] = {}

    for index, tool_call in enumerate(tool_calls):
        name = str(tool_call["function"]["name"])
        call_id = str(tool_call["id"])
        try:
            arguments = json.loads(
                tool_call["function"]["arguments"]
            )
        except json.JSONDecodeError as exc:
            immediate_results[index] = (
                f"Error: invalid tool arguments: {exc}"
            )
            continue

        print(f"-> {name}: {arguments}")
        permission = check_permission(
            name,
            arguments,
            self.permission_mode,
            self.mode,
        )

        if permission.action == "deny":
            immediate_results[index] = (
                f"Action denied: {permission.message}"
            )
            continue

        if permission.action == "confirm":
            key = f"{name}:{permission.message}"
            allowed = (
                key in self.confirmed_actions
                or self._confirm(permission.message)
            )
            if not allowed:
                immediate_results[index] = (
                    "User denied this action."
                )
                continue
            self.confirmed_actions.add(key)

        tool = self.tools.get(name)
        jobs.append(
            ToolJob(
                index=index,
                call_id=call_id,
                name=name,
                arguments=arguments,
                concurrency_safe=bool(
                    tool is not None
                    and tool.concurrency_safe
                ),
            )
        )

    return jobs, immediate_results
```

用户确认发生在 `_prepare_tool_jobs()`，也就是主线程。Scheduler 的线程只会收到已经 allow 的任务。

### 13.8.6 增加统一执行方法

```python
def _run_tool_calls(self, tool_calls: list[dict]) -> list[dict]:
    jobs, result_by_index = self._prepare_tool_jobs(tool_calls)

    outcomes = self.scheduler.execute(
        jobs,
        execute_one=lambda job: self._execute_tool(
            job.name,
            job.arguments,
        ),
        cancelled=self.cancelled,
    )
    for outcome in outcomes:
        result_by_index[outcome.index] = outcome.content

    tool_messages: list[dict] = []
    for index, tool_call in enumerate(tool_calls):
        tool_messages.append(
            {
                "role": "tool",
                "tool_call_id": tool_call["id"],
                "content": result_by_index.get(
                    index,
                    "Error: tool produced no result",
                ),
            }
        )
    return tool_messages
```

注意：Scheduler 返回的顺序已经恢复，但这里仍按原始 `tool_calls` 再组织一次，从协议层确保 `tool_call_id` 不会错配。

### 13.8.8 为什么本章不强行提前执行百炼工具

- 未来有明确完成事件的后端：复用同一个 Scheduler，在完成事件处提前提交。

## 13.9 Budget 与四层上下文

### 本节新增/优化功能及作用

| 新增或优化功能 | 作用 |
|---|---|
| `RunBudget` | 同时限制模型轮次、输入/输出 Token 和费用，防止 Agent 因循环或重试无限消耗。 |
| Budget 停止原因 | 明确区分正常完成、轮次耗尽、Token 超限、费用超限和用户取消，便于 CLI 与 Session 恢复。 |
| 结果规范化与落盘 | 先保存完整工具结果，再生成适合上下文的预览，保证信息可追溯。 |
| Snip / Microcompact | 优先压缩旧工具输出和低价值内容，尽量避免过早调用模型做整段摘要。 |
| Summary Compact | 上下文接近上限时总结旧历史，同时保留最近完整轮次和关键任务状态。 |
| Prompt Too Long 单次恢复 | 请求因上下文过长失败时强制压缩并只重试一次，避免无意义重试。 |

### 13.9.1 新建 `budget.py`

这一节不要先改 Agent 主循环。先单独做一个 `budget.py`，让它只负责三件事：

1. 记录模型调用了多少轮；
2. 记录 usage 里的输入、输出和缓存命中 Token；
3. 判断是否应该停止。

这样做的好处是：预算逻辑不会散落在 `agent.py`、`main.py` 和 `session.py` 里。后面要加 `--max-turns`、`--max-cost` 或保存恢复预算状态，只需要调用这里的对象。

#### 13.9.1.1 先明确 Budget 的输入和输出

Budget 不直接调用模型，也不直接打印内容。

它的输入是模型返回的 `usage`：

```python
{
    "prompt_tokens": 3000,
    "completion_tokens": 500,
    "prompt_tokens_details": {
        "cached_tokens": 2000
    }
}
```

它的输出是两类信息：

```python
budget.record_usage(usage)
reason = budget.stop_reason()
```

如果 `reason is None`，说明还可以继续运行；如果返回字符串，说明 Agent 应该停止，并把原因告诉用户。

#### 13.9.1.2 创建文件并加入最小导入

新建文件：

```text
mini_claude/budget.py
```

先写入：

```python
from __future__ import annotations

from dataclasses import dataclass
from typing import Any
```

这里使用 `Any` 是因为不同接口返回的 `usage` 形态不完全一样：

- 有时是普通 `dict`；
- 有时是 OpenAI SDK 对象；
- 有时字段名是 `prompt_tokens` / `completion_tokens`；
- 有时字段名可能是 `input_tokens` / `output_tokens`。

所以这一层要写得宽容一点。

#### 13.9.1.3 增加统一读取字段的小函数

先加：

```python
def _read_field(value: Any, name: str, default: Any = 0) -> Any:
    if value is None:
        return default
    if isinstance(value, dict):
        return value.get(name, default)
    return getattr(value, name, default)
```

这个函数解决的是“同一个 usage，有时像字典，有时像对象”的问题。

例如：

```python
usage["prompt_tokens"]
```

和：

```python
usage.prompt_tokens
```

都可以被统一写成：

```python
_read_field(usage, "prompt_tokens", 0)
```

这一步很小，但很重要。后面 `record_usage()` 就不会到处写 `isinstance()` 判断。

#### 13.9.1.4 定义预算上限 `BudgetLimits`

继续增加：

```python
@dataclass(frozen=True)
class BudgetLimits:
    max_turns: int | None = None
    max_cost_usd: float | None = None
    input_price_per_million: float = 0.0
    output_price_per_million: float = 0.0
    cache_read_price_per_million: float = 0.0
```

这里保存的是“限制条件”，不是运行过程中的统计数据。

字段含义：

| 字段 | 含义 |
|---|---|
| `max_turns` | 最多允许调用模型多少轮 |
| `max_cost_usd` | 估算费用达到多少美元后停止 |
| `input_price_per_million` | 每百万输入 Token 的价格 |
| `output_price_per_million` | 每百万输出 Token 的价格 |
| `cache_read_price_per_million` | 每百万缓存命中 Token 的价格 |

单价默认是 `0.0`，因为不同模型价格不同，不能写死在框架里。后面由 CLI 参数或环境变量传入。

#### 13.9.1.5 定义运行状态 `BudgetState`

继续增加：

```python
@dataclass
class BudgetState:
    limits: BudgetLimits
    turns: int = 0
    input_tokens: int = 0
    output_tokens: int = 0
    cache_read_tokens: int = 0
    cache_creation_tokens: int = 0
    estimated_cost_usd: float = 0.0
```

`BudgetLimits` 是规则，`BudgetState` 是当前已经花了多少。

这里把缓存分成两个字段：

- `cache_read_tokens`：这次命中了多少缓存；
- `cache_creation_tokens`：这次创建了多少缓存。

当前先只用 `cache_read_tokens` 估算费用。`cache_creation_tokens` 先记录下来，是为了后面你想更精细统计缓存创建成本时不用再改 Session 格式。

#### 13.9.1.6 增加 `record_usage()` 的外壳

在 `BudgetState` 中先增加方法边界：

```python
def record_usage(self, usage: Any | None) -> None:
    self.turns += 1
    if usage is None:
        return
```

注意：即使 `usage is None`，也要先 `self.turns += 1`。

原因是一次模型请求已经发生了，只是服务端没有返回 usage。预算中的“模型轮次”应该继续增长，否则网络异常或兼容接口漏返回 usage 时，Agent 可能一直跑下去。

#### 13.9.1.7 读取输入和输出 Token

继续在 `record_usage()` 中增加：

```python
prompt_tokens = int(
    _read_field(
        usage,
        "prompt_tokens",
        _read_field(usage, "input_tokens", 0),
    )
    or 0
)
output_tokens = int(
    _read_field(
        usage,
        "completion_tokens",
        _read_field(usage, "output_tokens", 0),
    )
    or 0
)
```

这里兼容两套命名：

| 常见字段 | 兼容字段 | 含义 |
|---|---|---|
| `prompt_tokens` | `input_tokens` | 输入 Token |
| `completion_tokens` | `output_tokens` | 输出 Token |

百炼走 OpenAI 兼容接口时，通常是 `prompt_tokens` 和 `completion_tokens`。但框架层最好不要只适配一个服务商。

#### 13.9.1.8 读取缓存命中 Token

继续增加：

```python
details = _read_field(usage, "prompt_tokens_details", None)
cached_tokens = int(
    _read_field(
        details,
        "cached_tokens",
        _read_field(
            usage,
            "cache_read_input_tokens",
            _read_field(usage, "cached_tokens", 0),
        ),
    )
    or 0
)
```

这段看起来长，是因为缓存字段在不同接口里可能放在不同位置：

- OpenAI 兼容格式常见位置：`usage.prompt_tokens_details.cached_tokens`
- 一些接口可能直接放：`usage.cache_read_input_tokens`
- 有的测试数据可能简化成：`usage.cached_tokens`

这一层只做兼容读取，不在这里判断缓存是否真的生效。缓存是否生效，后面通过输出 `cached_tokens > 0` 来验证。

#### 13.9.1.9 记录缓存创建 Token

继续增加：

```python
creation_tokens = int(
    _read_field(usage, "cache_creation_input_tokens", 0)
    or 0
)
```

这一步当前不影响停止判断，主要用于观察。

比如你验证 `cache_control` 时，就可以同时看：

- 第一次请求有没有创建缓存；
- 第二次请求有没有读到缓存。

#### 13.9.1.10 累加统计值

继续增加：

```python
self.input_tokens += prompt_tokens
self.output_tokens += output_tokens
self.cache_read_tokens += cached_tokens
self.cache_creation_tokens += creation_tokens
```

这里记录的是整个会话累计值，不是单轮值。

如果你连续问三次，`input_tokens` 会是三次模型请求的总输入 Token。这样 Session 恢复后，也可以继续从之前的预算状态往后累加。

#### 13.9.1.11 估算费用

继续增加：

```python
normal_input = max(0, prompt_tokens - cached_tokens)
self.estimated_cost_usd += (
    normal_input
    * self.limits.input_price_per_million
    / 1_000_000
)
self.estimated_cost_usd += (
    cached_tokens
    * self.limits.cache_read_price_per_million
    / 1_000_000
)
self.estimated_cost_usd += (
    output_tokens
    * self.limits.output_price_per_million
    / 1_000_000
)
```

这里故意把输入分成两部分：

```text
普通输入 Token = prompt_tokens - cached_tokens
缓存命中 Token = cached_tokens
```

因为命中缓存的输入 Token 通常更便宜。如果某个平台不区分缓存价格，可以让：

```python
cache_read_price_per_million = input_price_per_million
```

如果暂时不想算钱，就保持价格为 `0.0`，Budget 仍然可以统计轮次和 Token。

#### 13.9.1.12 增加停止原因 `stop_reason()`

在 `BudgetState` 中继续增加：

```python
def stop_reason(self) -> str | None:
    if (
        self.limits.max_turns is not None
        and self.turns >= self.limits.max_turns
    ):
        return (
            "达到模型调用轮次上限："
            f"{self.turns}/{self.limits.max_turns}"
        )
    if (
        self.limits.max_cost_usd is not None
        and self.estimated_cost_usd >= self.limits.max_cost_usd
    ):
        return (
            "达到费用上限："
            f"${self.estimated_cost_usd:.4f}/"
            f"${self.limits.max_cost_usd:.4f}"
        )
    return None
```

先判断轮次，再判断费用。原因是轮次最稳定，不依赖 usage 是否完整返回。

这里返回字符串，而不是直接 `print()` 或 `raise`，是为了让上层决定怎么处理：

- CLI 可以打印给用户；
- Agent Loop 可以把原因加入历史；
- Session 可以保存停止原因；
- 测试可以直接断言返回值。

#### 13.9.1.13 增加保存方法 `to_dict()`

继续增加：

```python
def to_dict(self) -> dict:
    return {
        "turns": self.turns,
        "input_tokens": self.input_tokens,
        "output_tokens": self.output_tokens,
        "cache_read_tokens": self.cache_read_tokens,
        "cache_creation_tokens": self.cache_creation_tokens,
        "estimated_cost_usd": self.estimated_cost_usd,

```

它只保存状态，不保存 `limits`。

原因是 `limits` 更像本次启动参数，例如今天你用 `--max-turns 10`，明天恢复同一个 Session 时可能改成 `--max-turns 20`。保存运行统计就够了。

#### 13.9.1.14 增加恢复方法 `restore()`

继续增加：

```python

    self.output_tokens = int(value.get("output_tokens", 0))
```

这里使用 `get(..., 0)` 是为了兼容旧 Session。

#### 13.9.1.15 最终状态核对

所有步骤都完成后，`budget.py` 的最终结构应该是下面这样。注意，这是核对用的最终状态，不是让你一开始就整段覆盖：

```python

from typing import Any

        return default
    if isinstance(value, dict):
        return value.get(name, default)

        if usage is None:
            return

        prompt_tokens = int(
            _read_field(
                usage,
                "prompt_tokens",
                _read_field(usage, "input_tokens", 0),

            _read_field(usage, "cache_creation_input_tokens", 0)
            or 0

        self.input_tokens += prompt_tokens
        self.output_tokens += output_tokens
        self.cache_read_tokens += cached_tokens
        self.cache_creation_tokens += creation_tokens

        normal_input = max(0, prompt_tokens - cached_tokens)
        self.estimated_cost_usd += (
            normal_input
            * self.limits.input_price_per_million
            / 1_000_000
        )
        self.estimated_cost_usd += (
            cached_tokens
            * self.limits.cache_read_price_per_million
            / 1_000_000
        )
        self.estimated_cost_usd += (
            output_tokens
            * self.limits.output_price_per_million
            / 1_000_000
        )

    def stop_reason(self) -> str | None:
        if (
            self.limits.max_turns is not None
            and self.turns >= self.limits.max_turns
        ):
            return (
                "达到模型调用轮次上限："
                f"{self.turns}/{self.limits.max_turns}"

            self.limits.max_cost_usd is not None

                f"${self.estimated_cost_usd:.4f}/"
                f"${self.limits.max_cost_usd:.4f}"
            )
        return None

    def to_dict(self) -> dict:
        return {
            "turns": self.turns,
            "input_tokens": self.input_tokens,
            "output_tokens": self.output_tokens,
            "cache_read_tokens": self.cache_read_tokens,
            "cache_creation_tokens": self.cache_creation_tokens,
            "estimated_cost_usd": self.estimated_cost_usd,
        }

    def restore(self, value: dict) -> None:

        self.input_tokens = int(value.get("input_tokens", 0))
        self.output_tokens = int(value.get("output_tokens", 0))
        self.cache_read_tokens = int(
            value.get("cache_read_tokens", 0)

        self.cache_creation_tokens = int(
            value.get("cache_creation_tokens", 0)
```

### 13.9.4 分层扩展 `context.py`

不要覆盖现有 `persist_large_result()`。这一节仍然沿用你已经写好的 `truncate_result()`，但要把它升级成可传入不同上限的通用截断函数。

为什么这里要改？

之前只有一个 `MAX_RESULT_CHARS`，所有工具结果都按同一个长度截断。现在新增了 `MAX_TOOL_RESULT_CHARS`，说明我们想让“工具消息进入历史时”使用更严格的限制。也就是说：

```text
普通结果展示：使用 MAX_RESULT_CHARS
历史中的工具结果：使用 MAX_TOOL_RESULT_CHARS
```

所以不要新增 `truncate_middle()`，也不要继续让 `budget_tool_results()` 调用单参数 `truncate_result(content)`。正确路线是扩展原函数：

```python
def truncate_result(result: str, limit: int = MAX_RESULT_CHARS) -> str:
    ...
```

这样旧调用不受影响，新调用也能传入更小的工具结果预算。

#### 13.9.4.1 补齐常量

检查 `context.py` 顶部常量区，确保有这些值：

```python
MAX_TOOL_RESULT_CHARS = 30_000
LARGE_RESULT_BYTES = 30 * 1024
MAX_RESULT_CHARS = 50_000

COMPACT_TRIGGER_CHARS = 80_000

KEEP_RECENT_TURNS = 3

    "[旧工具结果已压缩；如需完整内容，请重新读取原文件或持久化结果]"
)
SNIP_TRIGGER_CHARS = 55_000
```

如果你当前文件里已经有这些常量，就不要重复添加。

这里有两个容易混淆的上限：

- `MAX_RESULT_CHARS`：`truncate_result()` 使用，控制单条字符串最多保留多少字符；
- `MAX_TOOL_RESULT_CHARS`：`budget_tool_results()` 使用，控制历史中的工具结果最多保留多少字符。

#### 13.9.4.2 修改 `truncate_result()`，允许传入限制

把原来的：

```python

        return result
```

```python
    result: str,

        return result

    keep_each = (limit - 100) // 2

    return (
        result[:keep_each]
        + f"\n\n[... truncated {omitted} characters ...]\n\n"
        + result[-keep_each:]
    )
```

这一步是本节的核心小改动。它保留了原来的函数名，也保留了原来的默认行为，所以：

```python
truncate_result(result)
```

仍然等价于：

```python
truncate_result(result, MAX_RESULT_CHARS)
```

但后面可以写：

```python
truncate_result(content, MAX_TOOL_RESULT_CHARS)
```

#### 13.9.4.3 优化 `history_size()`

你当前可能写的是：

```python
def history_size(messages: list[dict]) -> int:
    return len(str(messages))
```

这个可以运行，但每次都会把整个列表转成一个大字符串。建议改成：

```python
def history_size(messages: list[dict]) -> int:
    return sum(len(str(message)) for message in messages)
```

这不是功能性大改，只是让统计逻辑更清楚。

#### 13.9.4.4 修改 `budget_tool_results()`，使用工具结果预算

在 `history_size()` 后面保留或新增：

```python
def budget_tool_results(messages: list[dict]) -> None:
    for message in messages:
        if message.get("role") != "tool":
            continue
        content = message.get("content")
        if isinstance(content, str):
            message["content"] = truncate_result(
                content,
                MAX_TOOL_RESULT_CHARS,
            )
```

这里才真正用到了 `MAX_TOOL_RESULT_CHARS`。

也就是说，大工具结果进入历史后，即使它没有触发落盘，或者落盘后的预览仍然偏长，也会在这一层被压到工具消息预算内。

#### 13.9.4.5 新增 `snip_stale_results()`

继续在 `budget_tool_results()` 后面增加：

```python
def snip_stale_results(messages: list[dict]) -> None:
    if history_size(messages) < SNIP_TRIGGER_CHARS:
        return

    indexes = [
        index
        for index, message in enumerate(messages)
        if message.get("role") == "tool"
    ]
    stale = indexes[:-KEEP_RECENT_TOOL_RESULTS]

    for index in stale:
        content = messages[index].get("content")
        if not isinstance(content, str):
            continue
        if content == SNIP_PLACEHOLDER:
            continue
        messages[index]["content"] = SNIP_PLACEHOLDER
```

它只替换旧工具结果的 `content`，不会删除整条 tool message。工具协议要求 assistant 的每个 `tool_call_id` 都要有对应的 `role=tool` 消息，直接删除旧工具消息会破坏历史结构。

#### 13.9.4.6 新增 `microcompact()`

继续增加：

```python
def microcompact(messages: list[dict]) -> None:
    last_tool_content: dict[str, int] = {}

    for index, message in enumerate(messages):
        if message.get("role") != "tool":
            continue
        content = message.get("content")
        if not isinstance(content, str) or not content:
            continue

        previous = last_tool_content.get(content)
        if previous is not None:
            messages[previous]["content"] = (
                "[重复工具结果已省略；相同内容见后续调用]"
            )
        last_tool_content[content] = index
```

这个函数解决重复工具结果。比如模型连续读取同一个文件两次，历史里会出现两段完全一样的 `read_file` 内容。它会保留后面那条完整结果，把前面重复的一条替换成说明文本。

#### 13.9.4.7 把原摘要逻辑拆成 `summary_compact()`

你现在的 `maybe_compact()` 已经包含摘要逻辑。不要重写 `render_for_summary()`、`summarize_messages()` 和 `find_recent_boundary()`，只把原 `maybe_compact()` 的主体搬进新函数：

```python
def summary_compact(
    messages: list[dict],
    client,
    model: str,
) -> list[dict]:
    if history_size(messages) < COMPACT_TRIGGER_CHARS:
        return messages

    boundary = find_recent_boundary(messages)
    if boundary == 0:
        return messages

    older = messages[:boundary]
    recent = messages[boundary:]
    summary = summarize_messages(older, client, model)

    print(f"(已将 {len(older)} 条旧消息压缩为摘要)")
    return [
        {
            "role": "user",
            "content": f"[Earlier conversation summary]\n{summary}",
        },
        {
            "role": "assistant",
            "content": "已了解此前摘要，将根据最近任务继续。",
        },
        *recent,
    ]
```

这样做以后，摘要压缩只是第四层，不再是 `maybe_compact()` 里的唯一逻辑。

#### 13.9.4.8 修改 `maybe_compact()`

最后把 `maybe_compact()` 改成四层流水线：

```python
def maybe_compact(
    messages: list[dict],
    client,
    model: str,
) -> list[dict]:
    budget_tool_results(messages)
    snip_stale_results(messages)
    microcompact(messages)
    return summary_compact(messages, client, model)
```

这里建议先使用 `deepcopy`，避免压缩函数直接改坏原始历史对象。

在文件顶部增加：

```python
from copy import deepcopy
```

然后把 `maybe_compact()` 写成：

```python
working = deepcopy(messages)
budget_tool_results(working)
snip_stale_results(working)
microcompact(working)
return summary_compact(working, client, model)
```

这样做的好处是：压缩只影响“准备发给模型的上下文副本”，不会提前破坏 `self.messages` 里保存的原始历史。后面做 Session 保存时，也更容易决定保存完整历史还是保存压缩历史。

## 13.10 Memory 补全

### 本节新增/优化功能及作用

| 新增或优化功能 | 作用 |
|---|---|
| 共享 Frontmatter 解析 | 为 Memory、Skills 和自定义 Agent 提供统一的 Markdown 元数据格式。 |
| 认知类型 Memory | 借鉴 HelloAgents 的 working / episodic / semantic / perceptual 分类，但当前只落地长期有用的 episodic 和 semantic。 |
| 会话工作区 | 每个对话在项目内 `.mini-agent/sessions/<session_id>/` 拥有独立目录，保存消息、工具结果和 working memory。 |
| Working Memory | 不再把上下文等同于短期记忆，而是保存当前目标、计划、观察、待办，以及尚未固化的记忆候选。 |
| 标签字段 tags | 将 user、project、feedback、reference 从“记忆类型”调整为“来源或主题标签”，避免类型语义混乱。 |
| 候选、重要性与整合 | 借鉴 HelloAgents 的 importance 和 consolidate 思路：信息先进入 working memory 成为候选，再将重要经历固化为 episodic，将稳定规则固化为 semantic。 |
| Memory 工具化 | 新增 working memory 读写、长期记忆搜索、固化和遗忘工具，让模型按需管理记忆。 |
| 可恢复遗忘 | `memory_forget` 将长期记忆移出活动目录并归档，而不是立即永久删除。 |
| 关键词按需检索 | `keyword_recall` 作为 `memory_search` 的低成本实现，不再每轮自动调用模型或注入所有记忆。 |
| 语义检索升级边界 | 本节不假装已经实现向量或模型语义选择；未来只替换 `memory_search` 内部实现。 |

### 13.10.0 先确定本项目的 Memory 分类

HelloAgents 第八章里的四种记忆类型是：

```text
working     工作记忆：当前任务中的临时信息
episodic    情景记忆：具体事件、经历、调试过程
semantic    语义记忆：稳定事实、规则、偏好、抽象知识
perceptual  感知记忆：图片、音频、截图、网页观察等外部感知输入
```

但 Mini Claude 当前是 Coding Agent，不需要把四类都做成同一种存储。

本项目当前采用两层存储：

```text
会话级工作记忆：working
长期项目记忆：episodic / semantic
```

这不是三个互不相关的文件类型，而是一条从短期状态到长期知识的演进路线：

```text
当前对话、工具结果、用户反馈
→ 更新 working memory
→ 产生 memory candidate
→ 继续在当前会话中观察和修正
→ importance 达到阈值后执行 consolidate
→ 具体经历固化为 episodic
→ 稳定规则、偏好或项目事实固化为 semantic
```

`working` 不会直接“改名”为 `episodic` 或 `semantic`。真正被升级的是 working memory 中的某一条候选信息；当前目标、计划、待办等普通工作状态仍然只属于本会话。

原因是：

| 类型 | 当前实现方式 | 原因 |
|---|---|---|
| `working` | 保存在当前会话目录 | 记录当前目标、计划、观察、待办，不等同于完整上下文。 |
| `episodic` | 保存在 `.mini-memory/` | 适合保存“某次调试过程、某个坑、某天开发经历”。 |
| `semantic` | 保存在 `.mini-memory/` | 适合保存“项目规则、用户偏好、稳定事实、长期约定”。 |
| `perceptual` | 预留 | 当前项目主要处理文本和代码，暂时没有图像、音频、截图等多模态输入。 |

之前的：

```text
user / project / feedback / reference
```

不再作为 `type`，而是作为 `tags`。它们描述“这条记忆来自哪里、属于什么主题”，不是记忆的认知类型。

最终格式是：

```markdown
---
name: python-style
description: 用户在 Python 项目中的长期代码风格偏好
type: semantic
tags: user, python, style
updated: 2026-08-14
---

用户偏好公共函数带类型标注，并优先使用标准库。
```

这样既借鉴 HelloAgents 的记忆理论，又不会为了对齐而过度设计。

### 13.10.0.1 先把 Session、Context 和 Memory 分清楚

不要把上下文直接等同于 Memory。

```text
Context
  本轮发给模型的材料，包括 system prompt、历史消息、工具结果和召回内容。

Session
  当前对话的运行记录，包括 messages、usage、工具结果、已激活工具和当前状态。

Working Memory
  当前任务的结构化短期状态，例如目标、计划、观察、待办、阻塞点和待评估记忆候选。

Long-term Memory
  跨会话复用的长期记忆，包括 episodic 和 semantic。
```

因此：

```text
keyword_recall 不是去查历史会话上下文
keyword_recall 是 memory_search 的低成本实现
```

历史会话可以以后单独做 `session_search`，但不要把 `C:\Users\86151\.mini-agent` 或旧 Session 历史自动塞进 Memory。旧会话噪声多、容易过时，也容易浪费 Token。

### 13.10.0.2 会话工作区目录设计

从本章开始，不再把 Session、工具结果、working memory 分散保存。每个对话都在项目内拥有独立目录：

```text
myclaude/myclaude/.mini-agent/
└── sessions/
    └── <session_id>/
        ├── messages.json
        ├── state.json
        ├── working-memory.json
        └── tool-results/
            ├── read_file-20260816-120001.txt
            └── run_shell-20260816-120030.txt
```

各文件职责：

| 文件或目录 | 作用 |
|---|---|
| `messages.json` | 保存当前对话消息历史，替代散落的 last-session 文件。 |
| `state.json` | 保存预算、模式、已激活工具、usage 等可恢复状态。 |
| `working-memory.json` | 保存当前任务的短期结构化记忆。 |
| `tool-results/` | 保存本会话产生的大工具结果，避免所有会话混在一起。 |

长期 Memory 仍然放在：

```text
myclaude/myclaude/.mini-memory/
├── python-style.md
├── day3-context-bug.md
└── ...
```

这两个目录不能混用：

```text
.mini-agent/sessions/<session_id>/  当前会话运行状态
.mini-memory/                       跨会话长期记忆
```

这样做以后，工具结果路径可以从：

```text
.mini-agent/tool-results/xxx.txt
```

升级为：

```text
.mini-agent/sessions/<session_id>/tool-results/xxx.txt
```

同一个项目里的不同对话不会再互相污染工具结果和 working memory。

### 13.10.0.3 Memory 写入不是只靠用户说“记住”

HelloAgents 第八章的 Memory 不是简单的“用户说记住才保存”，而是一套生命周期：

```text
add candidate → search → forget → consolidate
```

其中最重要的是两个概念：

```text
importance    这条信息有多重要
consolidate   把短期信息整合成长期记忆
forget        让已经过时或错误的长期记忆退出活动集合
```

Mini Claude 在本节实现轻量但完整的 `working memory` 存储，并把长期记忆写入建立在它之上：

```text
当前会话 / 工具结果 / 用户反馈
→ working_memory_update 更新当前任务状态
→ 值得复用的信息进入 memory_candidates
→ 根据 importance 判断是否值得长期保存
→ memory_add 执行 consolidate
→ 重要的具体经历保存为 episodic
→ 稳定规则、偏好、项目事实保存为 semantic
```

触发写入的来源分三类：

| 来源 | 默认去向 | 示例 |
|---|---|---|
| 用户明确表达长期偏好 | `semantic` | “以后教程不要写常见问题。” |
| 用户纠正 Agent 的重要行为 | `episodic` 或 `semantic` | “你没看当前代码就写教程。” |
| 任务中产生可复用修复经验 | `episodic` | “Prompt Too Long 不能走普通重试。” |

注意：写入 Memory 不是把每轮对话都存进去。只有满足下面条件之一，才进入候选：

```text
1. 用户明确表达长期偏好或规则；
2. 用户对 Agent 行为做了明确纠正；
3. 当前任务产生了以后可能复用的修复经验；
4. 同类问题重复出现，说明它不是一次性信息；
5. 该信息不能通过读取当前代码或文档快速得到。
```

因此本项目的策略是：

```text
读取 working memory：模型需要当前任务状态时按需调用工具
写入 working memory：目标、计划和执行状态变化时按需更新
写入记忆候选：发现可能跨会话复用的信息时写入 working memory
固化长期记忆：必须经过 importance 判断并调用 memory_add
固化 semantic：比固化 episodic 更谨慎，需要确认信息已经稳定
遗忘长期记忆：必须调用 memory_forget 并经过用户确认
```

### 13.10.1 新建共享 `frontmatter.py`

Memory、Skills 和自定义 Agent 都需要元数据。新建 `mini_claude/frontmatter.py`：

```python
from __future__ import annotations


def parse_frontmatter(text: str) -> tuple[dict[str, str], str]:
    normalized = text.replace("\r\n", "\n")
    if not normalized.startswith("---\n"):
        return {}, text.strip()

    end = normalized.find("\n---\n", 4)
    if end < 0:
        return {}, text.strip()

    header = normalized[4:end]
    body = normalized[end + 5 :].strip()
    metadata: dict[str, str] = {}

    for raw_line in header.splitlines():
        line = raw_line.strip()
        if not line or line.startswith("#") or ":" not in line:
            continue
        key, value = line.split(":", 1)
        clean_key = key.strip().lower()
        clean_value = value.strip().strip('"\'')
        if clean_key:
            metadata[clean_key] = clean_value

    return metadata, body
```

这个教学解析器只处理 `key: value`。当前 Memory、Skill 和 Agent 元数据都不需要嵌套 YAML，因此不用额外安装 PyYAML。

6. 增加 `consolidate_memory_candidates()`，只把达到阈值且经过选择的候选保存为 `episodic` 或 `semantic`。
7. 增加 `forget_memory()`，把过时记忆移动到 `.mini-memory/.forgotten/`，使它退出活动集合但仍可恢复。
8. 关键词版本验证通过后，把 `keyword_recall()` 包装成 `memory_search` 工具；未来如果要做语义召回，再升级工具内部实现。

下面的大代码块是第三阶段完成后的核对版本，不是第一步要复制的文件：

```python
from __future__ import annotations

from dataclasses import dataclass
from pathlib import Path
import re
from datetime import date

from mini_claude.frontmatter import parse_frontmatter


MEMORY_TYPES = {"episodic", "semantic"}


@dataclass(frozen=True)
class MemoryEntry:
    name: str
    description: str
    memory_type: str
    tags: list[str]
    updated: str
    path: Path
    content: str


@dataclass(frozen=True)
class MemoryCandidate:
    content: str
    memory_type: str
    tags: list[str]
    importance: float
    reason: str


def load_memories(project_root: Path) -> list[MemoryEntry]:
    memory_dir = project_root / ".mini-memory"
    if not memory_dir.is_dir():
        return []

    entries: list[MemoryEntry] = []
    for path in sorted(memory_dir.glob("*.md")):
        if path.name.upper() == "MEMORY.MD":
            continue
        try:
            raw = path.read_text(encoding="utf-8")
        except OSError:
            continue

        metadata, body = parse_frontmatter(raw)
        if not body:
            continue

        memory_type = metadata.get("type", "semantic")
        if memory_type not in MEMORY_TYPES:
            memory_type = "semantic"

        tags = [
            tag.strip()
            for tag in metadata.get("tags", "").split(",")
            if tag.strip()
        ]

        entries.append(
            MemoryEntry(
                name=metadata.get("name", path.stem),
                description=metadata.get(
                    "description",
                    body.splitlines()[0][:120],
                ),
                memory_type=memory_type,
                tags=tags,
                updated=metadata.get("updated", ""),
                path=path,
                content=body,
            )
        )
    return entries


def slugify_name(text: str) -> str:
    words = re.findall(r"[a-zA-Z0-9_\u4e00-\u9fff]+", text)
    name = "-".join(words[:6]).lower()
    return name or "memory"


def score_memory_candidate(
    content: str,
    tags: list[str],
) -> float:
    score = 0.0
    lowered = content.lower()

    if any(tag in tags for tag in ("user", "preference", "rule")):
        score += 0.35
    if any(tag in tags for tag in ("bug", "fix", "feedback")):
        score += 0.25
    if any(
        marker in lowered
        for marker in (
            "以后",
            "不要",
            "必须",
            "规则",
            "报错",
            "traceback",
            "error",
        )
    ):
        score += 0.25
    if len(content) >= 30:
        score += 0.15

    return min(score, 1.0)


def save_memory_entry(
    project_root: Path,
    candidate: MemoryCandidate,
) -> Path | None:
    if candidate.memory_type not in MEMORY_TYPES:
        return None
    if candidate.importance < 0.7:
        return None

    memory_dir = project_root / ".mini-memory"
    memory_dir.mkdir(parents=True, exist_ok=True)

    name = slugify_name(candidate.content)
    path = memory_dir / f"{name}.md"
    counter = 2
    while path.exists():
        path = memory_dir / f"{name}-{counter}.md"
        counter += 1

    path.write_text(
        (
            "---\n"
            f"name: {path.stem}\n"
            f"description: {candidate.reason}\n"
            f"type: {candidate.memory_type}\n"
            f"tags: {', '.join(candidate.tags)}\n"
            f"importance: {candidate.importance:.2f}\n"
            f"updated: {date.today().isoformat()}\n"
            "---\n\n"
            f"{candidate.content.strip()}\n"
        ),
        encoding="utf-8",
    )
    return path


def consolidate_memory_candidates(
    project_root: Path,
    candidates: list[MemoryCandidate],
) -> list[Path]:
    saved: list[Path] = []
    for candidate in candidates:
        path = save_memory_entry(project_root, candidate)
        if path is not None:
            saved.append(path)
    return saved


def forget_memory(
    project_root: Path,
    name: str,
) -> Path | None:
    matches = [
        item
        for item in load_memories(project_root)
        if item.name == name
    ]
    if len(matches) != 1:
        return None
    entry = matches[0]

    forgotten_dir = project_root / ".mini-memory" / ".forgotten"
    forgotten_dir.mkdir(parents=True, exist_ok=True)
    target = forgotten_dir / entry.path.name
    counter = 2
    while target.exists():
        target = forgotten_dir / (
            f"{entry.path.stem}-{counter}{entry.path.suffix}"
        )
        counter += 1

    entry.path.replace(target)
    return target


def extract_keywords(text: str) -> set[str]:
    lower = text.lower()
    english = {
        word
        for word in re.findall(r"[a-z0-9_]+", lower)
        if len(word) > 2
    }
    chinese_text = "".join(
        re.findall(r"[\u4e00-\u9fff]", lower)
    )
    chinese = {
        chinese_text[index : index + 2]
        for index in range(max(0, len(chinese_text) - 1))
    }
    return english | chinese


def format_memories(entries: list[MemoryEntry]) -> str:
    if not entries:
        return ""
    blocks = [
        (
            f"## {entry.name} ({entry.memory_type})\n"
            f"tags: {', '.join(entry.tags) or 'none'}\n"
            f"{entry.content}"
        )
        for entry in entries
    ]
    return (
        "# Memory\n"
        "以下内容是相关长期记忆，可能过时；涉及当前代码时必须重新核实。\n\n"
        + "\n\n".join(blocks)
    )


def keyword_recall(
    query: str,
    project_root: Path,
    limit: int = 3,
    memory_type: str = "any",
) -> str:
    query_words = extract_keywords(query)
    if not query_words:
        return ""

    scored: list[tuple[int, MemoryEntry]] = []
    for entry in load_memories(project_root):
        if memory_type != "any" and entry.memory_type != memory_type:
            continue
        searchable = (
            f"{entry.name} {entry.description} "
            f"{entry.memory_type} {' '.join(entry.tags)} "
            f"{entry.content}"
        )
        score = len(query_words & extract_keywords(searchable))
        if score > 0:
            scored.append((score, entry))

    selected = [
        entry
        for _, entry in sorted(
            scored,
            key=lambda item: item[0],
            reverse=True,
        )[:limit]
    ]
    return format_memories(selected)

```

这套写入流程是 HelloAgents 的轻量版。这里的 `MemoryCandidate` 不是每轮对话的副本，而是稍后由 `working_memory.py` 保存在当前会话中的待整合信息：

```text
working memory → 产生 MemoryCandidate
MemoryCandidate → 在当前会话中继续观察、纠正或去重
importance >= 0.7 → memory_add 可以将它固化为长期记忆
episodic → 保存具体经历
semantic → 保存稳定规则
forget → 将过时或错误记忆移到 .forgotten，不参与后续搜索
```

当前先用规则函数 `score_memory_candidate()` 评分，不调用模型判断重要性。等项目稳定后，再把评分逻辑替换成模型评估或混合评分。

这里的 forget 采用可恢复归档，而不是 `unlink()` 永久删除。`load_memories()` 只扫描 `.mini-memory/*.md`，不会进入 `.forgotten/`，因此被遗忘的记忆会立即退出 `memory_search`，但用户仍能手动恢复文件。

### 13.10.5 新建 `working_memory.py`

Working Memory 不是历史上下文全文，而是当前任务状态。新建 `mini_claude/working_memory.py`：

```python
from __future__ import annotations

from dataclasses import dataclass, field
import json
from pathlib import Path


@dataclass
class WorkingMemoryCandidate:
    content: str
    suggested_type: str
    tags: list[str] = field(default_factory=list)
    importance: float = 0.0
    reason: str = ""

    def to_dict(self) -> dict:
        return {
            "content": self.content,
            "suggested_type": self.suggested_type,
            "tags": self.tags,
            "importance": self.importance,
            "reason": self.reason,
        }

    @classmethod
    def from_dict(cls, value: dict) -> "WorkingMemoryCandidate":
        suggested_type = str(
            value.get("suggested_type", "episodic")
        )
        if suggested_type not in {"episodic", "semantic"}:
            suggested_type = "episodic"
        return cls(
            content=str(value.get("content", "")),
            suggested_type=suggested_type,
            tags=[str(item) for item in value.get("tags", [])],
            importance=float(value.get("importance", 0.0)),
            reason=str(value.get("reason", "")),
        )


@dataclass
class WorkingMemory:
    goal: str = ""
    plan: list[str] = field(default_factory=list)
    observations: list[str] = field(default_factory=list)
    todos: list[str] = field(default_factory=list)
    blockers: list[str] = field(default_factory=list)
    memory_candidates: list[WorkingMemoryCandidate] = field(
        default_factory=list
    )

    def to_dict(self) -> dict:
        return {
            "goal": self.goal,
            "plan": self.plan,
            "observations": self.observations,
            "todos": self.todos,
            "blockers": self.blockers,
            "memory_candidates": [
                candidate.to_dict()
                for candidate in self.memory_candidates
            ],
        }

    @classmethod
    def from_dict(cls, value: dict) -> "WorkingMemory":
        return cls(
            goal=str(value.get("goal", "")),
            plan=list(value.get("plan", [])),
            observations=list(value.get("observations", [])),
            todos=list(value.get("todos", [])),
            blockers=list(value.get("blockers", [])),
            memory_candidates=[
                WorkingMemoryCandidate.from_dict(item)
                for item in value.get("memory_candidates", [])
                if isinstance(item, dict)
            ],
        )


def load_working_memory(path: Path) -> WorkingMemory:
    if not path.exists():
        return WorkingMemory()
    try:
        return WorkingMemory.from_dict(
            json.loads(path.read_text(encoding="utf-8"))
        )
    except Exception:
        return WorkingMemory()


def save_working_memory(
    path: Path,
    memory: WorkingMemory,
) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(
        json.dumps(memory.to_dict(), ensure_ascii=False, indent=2),
        encoding="utf-8",
    )
```

`memory_candidates` 保存的是“可能值得跨会话复用，但尚未固化”的信息。它与 `goal`、`plan` 等普通工作状态同处一个会话文件，但只有候选会进入后面的 consolidate 流程。

例如一次修复完成后，working memory 可以暂时保存：

```json
{
  "content": "Prompt Too Long 应先压缩上下文，再额外重试一次。",
  "suggested_type": "episodic",
  "tags": ["project", "bug", "context"],
  "importance": 0.85,
  "reason": "本次调试得到的可复用修复经验"
}
```

此时它仍然只属于当前 Session。模型后续发现结论不准确时，可以先修改或删除候选，而不会污染长期记忆。

这个文件保存到：

```text
.mini-agent/sessions/<session_id>/working-memory.json
```

它跟 `.mini-memory/*.md` 不同：working memory 只属于当前对话，恢复这个会话时才恢复它，不会自动影响其他会话。

### 13.10.6 Memory 工具化

长期 Memory 不再每轮自动语义查询，而是做成工具，让模型在需要时主动查。

本节实现五个工具：

```text
working_memory_read      读取当前会话 working memory
working_memory_update    更新当前会话状态，也可以追加待整合记忆候选
memory_search            查询 .mini-memory 的 episodic / semantic
memory_add               将 working memory 中选中的候选固化为长期记忆
memory_forget            让过时或错误的长期记忆退出活动集合
```

工具权限建议：

| 工具 | 权限 | 原因 |
|---|---|---|
| `working_memory_read` | 只读 | 只是读取当前会话状态。 |
| `working_memory_update` | 写入但低风险 | 只写当前会话的 `working-memory.json`。 |
| `memory_search` | 只读 | 查询长期记忆，不修改文件。 |
| `memory_add` | 需要确认 | 会把当前会话候选固化到 `.mini-memory/*.md`，影响后续会话。 |
| `memory_forget` | 需要确认 | 会把长期记忆移到 `.forgotten/`，使后续会话不再检索它。 |

然后在同一个类中实现 `run()`。普通状态更新和候选更新都必须落回当前 Session：

```python
    def run(self, args: dict, context: ToolContext) -> str:
        workspace = context.session_workspace
        if workspace is None:
            return "Error: session workspace is not available."

        memory = load_working_memory(
            workspace.working_memory_file
        )
        action = str(args.get("action", ""))

        if action == "set_goal":
            memory.goal = str(args.get("value", "")).strip()

        elif action == "replace_plan":
            items = args.get("items")
            if not isinstance(items, list):
                return "Error: replace_plan requires items."
            memory.plan = [str(item) for item in items]

        elif action in {
            "add_observation",
            "add_todo",
            "add_blocker",
        }:
            value = str(args.get("value", "")).strip()
            if not value:
                return f"Error: {action} requires value."
            target = {
                "add_observation": memory.observations,
                "add_todo": memory.todos,
                "add_blocker": memory.blockers,
            }[action]
            target.append(value)

        elif action in {"complete_todo", "remove_blocker"}:
            index = int(args.get("index", -1))
            target = (
                memory.todos
                if action == "complete_todo"
                else memory.blockers
            )
            if index < 0 or index >= len(target):
                return "Error: state item does not exist."
            target.pop(index)

        elif action in {"add_candidate", "update_candidate"}:
            value = args.get("candidate")
            if not isinstance(value, dict):
                return f"Error: {action} requires candidate."

            content = str(value.get("content", "")).strip()
            tags = [str(tag) for tag in value.get("tags", [])]
            suggested_type = str(
                value.get("suggested_type", "episodic")
            )
            reason = str(value.get("reason", "")).strip()
            if not content or not reason:
                return "Error: candidate content and reason are required."
            if suggested_type not in {"episodic", "semantic"}:
                return "Error: invalid suggested memory type."

            importance = score_memory_candidate(content, tags)
            if importance < WORKING_CANDIDATE_THRESHOLD:
                return (
                    "Memory candidate skipped: "
                    f"importance={importance:.2f}."
                )

            candidate = WorkingMemoryCandidate(
                content=content,
                suggested_type=suggested_type,
                tags=tags,
                importance=importance,
                reason=reason,
            )
            if action == "add_candidate":
                duplicate = any(
                    item.content == candidate.content
                    for item in memory.memory_candidates
                )
                if duplicate:
                    return "Memory candidate already exists."
                memory.memory_candidates.append(candidate)
            else:
                index = int(args.get("index", -1))
                if index < 0 or index >= len(
                    memory.memory_candidates
                ):
                    return "Error: memory candidate does not exist."
                memory.memory_candidates[index] = candidate

        elif action == "remove_candidate":
            index = int(args.get("index", -1))
            if index < 0 or index >= len(memory.memory_candidates):
                return "Error: memory candidate does not exist."
            memory.memory_candidates.pop(index)

        else:
            return f"Error: unsupported working memory action: {action}"

        save_working_memory(
            workspace.working_memory_file,
            memory,
        )
        return json.dumps(
            memory.to_dict(),
            ensure_ascii=False,
            indent=2,
        )
```

模型不能直接指定 importance；工具根据内容和标签计算，避免模型为了强行写入长期记忆而随意给出 `1.0`。

```python
                    "description": "memory_candidates 中的候选下标",
                },
                "memory_type": {
                    "type": "string",
                    "enum": ["semantic", "episodic"],
                    "description": "可选；确认固化时修正候选类型",
                },
            },
            "required": ["candidate_index"],
            "additionalProperties": False,
        }

    def run(self, args: dict, context: ToolContext) -> str:
        workspace = context.session_workspace
        if workspace is None:
            return "Error: session workspace is not available."

        working = load_working_memory(
            workspace.working_memory_file
        )
        index = int(args["candidate_index"])
        if index < 0 or index >= len(working.memory_candidates):
            return "Error: memory candidate does not exist."

        draft = working.memory_candidates[index]
        memory_type = str(
            args.get("memory_type") or draft.suggested_type
        )
        if memory_type not in {"semantic", "episodic"}:
            return "Error: invalid memory type."
        candidate = MemoryCandidate(
            content=draft.content,
            memory_type=memory_type,
            tags=draft.tags,
            importance=draft.importance,
            reason=draft.reason,
        )
        saved = consolidate_memory_candidates(
            context.project_root,
            [candidate],
        )
        if not saved:
            return "Memory candidate skipped: importance too low."

        working.memory_candidates.pop(index)
        save_working_memory(
            workspace.working_memory_file,
            working,
        )
        return f"Memory saved: {saved[0].relative_to(context.project_root)}"
```

固化成功后从 working memory 删除候选，避免同一条内容被重复升级。

#### 13.10.6.6 实现 `MemoryForgetTool`

遗忘使用 Memory 的 `name` 精确匹配，并移动到可恢复归档目录：

```python
class MemoryForgetTool(Tool):
    def __init__(self) -> None:
        super().__init__(
            "memory_forget",
            "遗忘过时或错误的长期记忆；文件会移入可恢复归档目录。",
        )

    def parameters(self) -> dict:
        return {
            "type": "object",
            "properties": {
                "name": {
                    "type": "string",
                    "description": "memory_search 返回的精确记忆名称",
                },
            },
            "required": ["name"],
            "additionalProperties": False,
        }

    def run(self, args: dict, context: ToolContext) -> str:
        name = str(args.get("name", "")).strip()
        if not name:
            return "Error: memory name is required."

        archived = forget_memory(context.project_root, name)
        if archived is None:
            return "Error: memory does not exist or name is not unique."
        return (
            "Memory forgotten and archived: "
            f"{archived.relative_to(context.project_root)}"
        )
```

```python
import json
from pathlib import Path

from mini_claude.session_workspace import SessionWorkspace


LEGACY_SESSION_DIR = Path.home() / ".mini-agent"


def _read_messages(path: Path) -> list[dict] | None:
    if not path.is_file():
        return None
    try:
        value = json.loads(path.read_text(encoding="utf-8"))
    except (OSError, json.JSONDecodeError):
        return None
    return value if isinstance(value, list) else None


def save_session(
    workspace: SessionWorkspace,
    messages: list[dict],
) -> None:
    workspace.root.mkdir(parents=True, exist_ok=True)
    workspace.messages_file.write_text(
        json.dumps(messages, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )


def load_session(workspace: SessionWorkspace) -> list[dict]:
    current = _read_messages(workspace.messages_file)
    if current is not None:
        return current

    legacy = LEGACY_SESSION_DIR / f"{workspace.session_id}.json"
    return _read_messages(legacy) or []
```

### 13.10.8 为什么保留关键词搜索

HelloAgents 的 Memory 核心是 `search`，不是必须一开始就用向量库或模型筛选。

```text

semantic_recall = 未来可选增强
```

也就是说，关键词搜索不是“上下文召回”，而是 Memory Search 的第一版实现。它可以继续存在，但触发方式从“每轮自动塞进 prompt”改成“模型按需调用 memory_search”。

### 13.10.9 写入 Memory 的正规触发流程

本节在 `memory.py` 中提供长期存储能力，在 `working_memory.py` 中保存候选，但不要让 Agent 每轮自动落盘所有内容。正规流程是：

```text
当前目标、计划或执行状态发生变化
→ working_memory_update 更新普通工作状态
→ 发现可能复用的用户反馈、工具错误或修复经验
→ score_memory_candidate() 计算 importance
→ importance 较低：不创建候选，信息只留在消息历史或普通 observation
→ importance 较高：追加到 working-memory.json 的 memory_candidates
→ 在当前任务后续步骤中继续验证、修正和去重
→ 候选仍有效且 importance >= 0.7
→ 调用 memory_add，并由权限层确认长期写入
→ 具体经历固化为 episodic
→ 已稳定的规则、偏好或项目事实固化为 semantic
→ 固化成功后从 working memory 删除该候选
```

这里需要区分两种“自动”：

```text
自动维护 working memory：允许，但只在状态确实变化时调用，不是每轮强制执行
自动写入长期 memory：不允许，必须选择候选、通过阈值并经过写权限确认
自动遗忘长期 memory：不允许，必须精确指定记忆名称并经过写权限确认
```

触发示例：

```text
“以后教程不要写常见问题”
→ semantic，tags: user, docs, preference

“第 13 章 truncate_middle 与当前代码冲突”
→ episodic，tags: docs, bug, feedback

“项目根目录是 myclaude”
→ semantic，tags: project, path
```

这样既不是“用户必须说记住才保存”，也不是“什么都自动保存”。Working memory 提供缓冲区，importance 控制候选质量，权限确认控制跨会话影响，三层边界共同避免长期记忆污染。

当 `memory_search` 返回的内容已经过时、错误或与新规则冲突时，不要继续用新记忆覆盖旧文件并让两条规则同时存在。正规遗忘流程是：

```text
memory_search 找到旧记忆
→ 用当前代码、文档或用户确认它确实失效
→ 调用 memory_forget(name=精确名称)
→ 用户确认
→ 旧文件移入 .mini-memory/.forgotten/
→ 如有新的稳定规则，再通过 working candidate → memory_add 写入新记忆
```

```python
from pathlib import Path
```

```python
from mini_claude.frontmatter import parse_frontmatter


SKILL_NAME_PATTERN = re.compile(r"^[a-zA-Z0-9_-]+$")


@dataclass(frozen=True)

@dataclass(frozen=True)
class SkillInvocation:
    skill: SkillSpec
    arguments: str

    def render(self) -> str:
        if not self.arguments:
            return self.skill.content
        return (
            f"{self.skill.content}\n\n"
            f"# 用户参数\n{self.arguments}"
        )


def load_skill(path: Path) -> SkillSpec | None:
    try:
        raw = path.read_text(encoding="utf-8")
    except OSError:
        return None

    metadata, content = parse_frontmatter(raw)
    if not content:
        return None

    name = metadata.get("name", path.stem)
    if not SKILL_NAME_PATTERN.fullmatch(name):
        return None
    context = metadata.get("context", "inline").lower()
    if context not in {"inline", "fork"}:
        context = "inline"

    return SkillSpec(
        name=name,
        description=metadata.get(
            "description",
            content.splitlines()[0][:120],
        ),
        content=content,
        context=context,
        source=path,
    )


def discover_skills(project_root: Path) -> dict[str, SkillSpec]:
    user_dir = Path.home() / ".mini-agent" / "skills"
    project_dir = project_root / ".mini-skills"
    skills: dict[str, SkillSpec] = {}

    # 先用户级，后项目级；项目同名 Skill 覆盖用户级。
    for directory in (user_dir, project_dir):
        if not directory.is_dir():
            continue
        for path in sorted(directory.glob("*.md")):
            skill = load_skill(path)
            if skill is not None:
                skills[skill.name] = skill
    return skills


def resolve_skill(
    text: str,
    project_root: Path,
) -> SkillInvocation | None:
    if not text.startswith("/"):
        return None

    name, _, arguments = text[1:].partition(" ")
    if not SKILL_NAME_PATTERN.fullmatch(name):
        return None

    skill = discover_skills(project_root).get(name)
    if skill is None:
        return None
    return SkillInvocation(
        skill=skill,
        arguments=arguments.strip(),
    )


def format_skill_summary(project_root: Path) -> str:
    skills = discover_skills(project_root)
    if not skills:
        return ""
    lines = [
        f"- /{skill.name}: {skill.description} "
        f"(context={skill.context})"
        for skill in skills.values()
    ]
    return "# 可用 Skills\n" + "\n".join(lines)
```

### 13.12.1 新建 `plan.py`

Plan 文件放在项目的 `.mini-agent/plans/` 中，既能被现有文件工具访问，又不会逃出 `project_root`。

```python
from __future__ import annotations

from dataclasses import dataclass
from pathlib import Path


@dataclass
class PlanState:
    session_id: str
    project_root: Path
    active: bool = False
    awaiting_review: bool = False

    @property
    def relative_path(self) -> str:
        return (
            f".mini-agent/plans/plan-{self.session_id}.md"
        )

    @property
    def absolute_path(self) -> Path:
        return self.project_root / self.relative_path

    def enter(self) -> str:
        self.absolute_path.parent.mkdir(
            parents=True,
            exist_ok=True,
        )
        if not self.absolute_path.exists():
            self.absolute_path.write_text(
                "# Implementation Plan\n",
                encoding="utf-8",
            )
        self.active = True
        self.awaiting_review = False
        return (
            "已进入 Plan Mode。唯一允许修改的文件："
            f"{self.relative_path}"
        )

    def exit_for_review(self) -> str:
        if not self.active:
            return "Error: 当前没有处于 Plan Mode"
        if not self.absolute_path.is_file():
            return "Error: Plan 文件不存在"
        content = self.absolute_path.read_text(
            encoding="utf-8"
        ).strip()
        if not content or content == "# Implementation Plan":
            return "Error: Plan 文件还是空的"
        self.active = False
        self.awaiting_review = True
        return "Plan 已提交，等待用户审批。"

    def read(self) -> str:
        try:
            return self.absolute_path.read_text(encoding="utf-8")
        except OSError:
            return ""

    def to_dict(self) -> dict:
        return {
            "session_id": self.session_id,
            "active": self.active,
            "awaiting_review": self.awaiting_review,
        }

    def restore(self, value: dict) -> None:
        self.active = bool(value.get("active", False))
        self.awaiting_review = bool(
            value.get("awaiting_review", False)
        )
```

## 13.13 Sub-Agent 类型补全

### 本节新增/优化功能及作用

| 新增或优化功能 | 作用 |
|---|---|
| `AgentSpec` | 用结构化配置描述子 Agent 的名称、职责、模型、工具和最大轮次。 |
| 内置 Agent 类型 | 提供 Explore、Plan、General 和 Verification 等稳定角色，避免所有子任务使用同一个提示词。 |
| 自定义 Agent 发现 | 从项目配置文件加载用户定义角色，而不是为每个角色新写 Python 类。 |
| 独立上下文 | 子 Agent 的大量探索不会直接占用主 Agent 消息历史。 |
| 工具与递归限制 | 防止只读 Agent 写文件，也防止子 Agent 无限制创建下一层 Agent。 |
| 结构化摘要回传 | 主 Agent 只接收结论、证据和关键路径，降低上下文膨胀。 |

### 13.13.1 AgentSpec

```python
@dataclass(frozen=True)
class AgentSpec:
    name: str
    description: str
    system_prompt: str
    allowed_tools: frozenset[str]
```

从项目 Agent 配置目录读取自定义定义，经过字段校验后注册进 `AgentRegistry`。工具 Schema 只向模型展示名称与描述；真正执行时再根据类型构建子 Agent。

### 13.13.3 完成标准

- 子 Agent 不能递归获得 `agent` 工具。
- 每种类型只获得白名单工具。
- 子 Agent 的长结果先持久化再回到主上下文。
- 未知 Agent 类型返回工具错误，不让主循环崩溃。

### 13.15.2 新建 `workspace.py`

本项目不让用户启动时手工列出所有参考目录。首次访问外部目录时动态授权，但程序内部仍维护读写根目录集合：

```python
from __future__ import annotations

from dataclasses import dataclass, field
from pathlib import Path


@dataclass
class WorkspacePolicy:
    workspace_root: Path
    read_roots: set[Path] = field(default_factory=set)
    write_roots: set[Path] = field(default_factory=set)

    def __post_init__(self) -> None:
        self.workspace_root = self.workspace_root.resolve()
        self.read_roots = {
            path.resolve() for path in self.read_roots
        }
        self.write_roots = {
            path.resolve() for path in self.write_roots
        }
        self.read_roots.add(self.workspace_root)
        self.write_roots.add(self.workspace_root)

    def resolve_path(self, raw_path: str) -> Path:
        raw = Path(raw_path)
        if raw.is_absolute():
            return raw.resolve()
        return (self.workspace_root / raw).resolve()

    def is_allowed(self, path: Path, access: str) -> bool:
        roots = (
            self.write_roots
            if access == "write"
            else self.read_roots | self.write_roots
        )
        return any(path.is_relative_to(root) for root in roots)

    def grant(self, root: Path, access: str) -> None:
        resolved = root.resolve()
        drive_root = Path(resolved.anchor)
        home_root = Path.home().resolve()
        if resolved in {drive_root, home_root}:
            raise PermissionError(
                "不能一次授权整个磁盘或用户主目录"
            )
        if access == "write":
            self.write_roots.add(resolved)
            self.read_roots.add(resolved)
        else:
            self.read_roots.add(resolved)

    def to_dict(self) -> dict:
        return {
            "workspace_root": str(self.workspace_root),
            "read_roots": sorted(map(str, self.read_roots)),
            "write_roots": sorted(map(str, self.write_roots)),
        }

    @classmethod
    def from_dict(cls, value: dict) -> "WorkspacePolicy":
        read_roots = {
            Path(item).resolve()
            for item in value.get("read_roots", [])
            if Path(item).is_dir()
        }
        write_roots = {
            Path(item).resolve()
            for item in value.get("write_roots", [])
            if Path(item).is_dir()
        }
        return cls(
            workspace_root=Path(value["workspace_root"]),
            read_roots=read_roots,
            write_roots=write_roots,
        )
```

`workspace_root` 默认同时可读写。外部 `read_roots` 只能读取；只有明确加入 `write_roots` 的目录才能修改。

### 13.15.4 外部路径在调度前申请授权

不能让 `resolve_project_path()` 在工具线程中直接调用 `input()`。只读工具可能并行执行，多个线程同时询问用户会打乱终端。因此外部路径授权必须在 `_prepare_tool_jobs()` 中、提交 Scheduler 之前完成。

在 `permissions.py` 增加：

```python
from dataclasses import dataclass
from pathlib import Path

from mini_claude.workspace import WorkspacePolicy


READ_PATH_TOOLS = {"read_file", "list_files", "grep_search"}
WRITE_PATH_TOOLS = {"write_file", "edit_file"}


@dataclass(frozen=True)
class PathAccessRequest:
    action: PermissionAction
    message: str = ""
    grant_root: Path | None = None
    access: str = "read"


def check_path_access(
    tool_name: str,
    arguments: dict,
    policy: WorkspacePolicy,
) -> PathAccessRequest:
    if tool_name not in READ_PATH_TOOLS | WRITE_PATH_TOOLS:
        return PathAccessRequest("allow")

    raw_path = str(arguments.get("path") or ".")
    path = policy.resolve_path(raw_path)
    access = (
        "write" if tool_name in WRITE_PATH_TOOLS else "read"
    )
    if policy.is_allowed(path, access):
        return PathAccessRequest("allow")

    grant_root = path if path.is_dir() else path.parent
    return PathAccessRequest(
        "confirm",
        f"允许本会话{access}外部目录：{grant_root}",
        grant_root=grant_root,
        access=access,
    )
```

然后在 Agent 的 `_prepare_tool_jobs()` 中，通过普通工具权限检查后、创建 `ToolJob` 前增加：

```python
policy = self.tool_context.workspace_policy
if policy is not None:
    path_access = check_path_access(
        name,
        arguments,
        policy,
    )
    if path_access.action == "confirm":
        allowed = self._confirm(path_access.message)
        if not allowed or path_access.grant_root is None:
            immediate_results[index] = (
                "User denied external path access."
            )
            continue
        try:
            policy.grant(
                path_access.grant_root,
                path_access.access,
            )
        except PermissionError as exc:
            immediate_results[index] = f"Action denied: {exc}"
            continue
        self._save_runtime_state()
```

授权发生在调度前，所以多个文件读取仍然可以并行，终端也不会出现多个线程同时等待输入。

### 13.15.5 文件工具继续做最终边界检查

动态授权不能替代工具内部检查。把 `file_tools.py` 中的解析函数改成：

```python
def resolve_project_path(
    raw_path: str,
    context: ToolContext,
    access: str = "read",
) -> Path:
    policy = context.workspace_policy
    if policy is None:
        project_root = context.project_root.resolve()
        path = (project_root / raw_path).resolve()
        if not path.is_relative_to(project_root):
            raise PermissionError(
                "只能访问当前项目目录中的文件"

        return path

    path = policy.resolve_path(raw_path)
    if not policy.is_allowed(path, access):
        raise PermissionError("该目录尚未获得本会话授权")
    return path
```

新建 `session_index.py`：

```python
from __future__ import annotations

import json
from pathlib import Path


INDEX_DIR = Path.home() / ".mini-agent"
INDEX_FILE = INDEX_DIR / "session-index.json"


def load_session_index() -> dict[str, str]:
    if not INDEX_FILE.is_file():
        return {}
    try:
        value = json.loads(INDEX_FILE.read_text(encoding="utf-8"))
    except (OSError, json.JSONDecodeError) as exc:
        raise RuntimeError(
            f"Session Index 无法读取：{INDEX_FILE}: {exc}"
        ) from exc
    if not isinstance(value, dict):
        raise RuntimeError("Session Index 必须是 JSON 对象")
    return {
        str(key): str(path)
        for key, path in value.items()
    }


def register_session(session_id: str, workspace_root: Path) -> None:
    INDEX_DIR.mkdir(parents=True, exist_ok=True)
    value = load_session_index()
    value[session_id] = str(workspace_root.resolve())

    temporary = INDEX_FILE.with_suffix(".tmp")
    temporary.write_text(
        json.dumps(value, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )
    temporary.replace(INDEX_FILE)


def find_session_root(session_id: str) -> Path | None:
    raw = load_session_index().get(session_id)
    if not raw:
        return None
    root = Path(raw).resolve()
    return root if root.is_dir() else None


def list_session_entries() -> list[dict[str, str]]:
    return [
        {
            "session_id": session_id,
            "workspace_root": workspace_root,
        }
        for session_id, workspace_root
        in load_session_index().items()
    ]
```

索引损坏时不能凭空猜测工作区。`find_session_root()` 返回 `None` 后，CLI 应明确报告“找不到 Session 对应的工作区”，而不是退回当前目录并创建空会话。

启动顺序必须是：

```text
新会话
→ workspace_root = --cwd 或 Path.cwd()
→ 生成 session_id
→ 写入 session-index.json
→ 创建 Agent 和 SessionWorkspace

恢复会话
→ 根据 session_id 查询 session-index.json
→ 找到原 workspace_root
→ 读取该工作区的 state.json
→ 恢复 WorkspacePolicy
→ 创建 Agent
```

`main()` 中确定工作区的核心流程为：

```python
if args.resume:
    session_id = args.resume
    workspace_root = find_session_root(session_id)
    if workspace_root is None:
        raise RuntimeError(
            f"找不到会话 {session_id!r} 对应的工作区"
        )
    if args.cwd is not None:
        requested = args.cwd.resolve()
        if requested != workspace_root:
            raise RuntimeError(
                "--resume 的工作区与 --cwd 不一致"
            )
else:
    session_id = uuid4().hex
    workspace_root = (args.cwd or Path.cwd()).resolve()
    if not workspace_root.is_dir():
        raise RuntimeError("工作区目录不存在")
    register_session(session_id, workspace_root)

workspace = create_session_workspace(
    workspace_root,
    session_id,
)
runtime_state = load_runtime_state(workspace.state_file)
workspace_value = runtime_state.get("workspace")
policy = (
    WorkspacePolicy.from_dict(workspace_value)
    if isinstance(workspace_value, dict)
    else WorkspacePolicy(workspace_root)
)

agent = MINI_CLUE_AGENT(
    session_id=session_id,
    permission_mode=args.permission_mode,
    model=args.model,
    project_root=workspace_root,
    workspace_policy=policy,
)
```

`--resume` 与 `--cwd` 同时出现时，`--cwd` 只能用于验证路径是否一致，不能静默改变旧 Session 的工作区。要操作另一个目录应创建新会话。

```python
class SessionStateError(RuntimeError):
    pass


def load_runtime_state(path: Path) -> dict:
    if not path.is_file():
        return {}
    try:
        value = json.loads(path.read_text(encoding="utf-8"))
    except OSError as exc:
        raise SessionStateError(
            f"无法读取运行状态：{path}: {exc}"
        ) from exc
    except json.JSONDecodeError as exc:
        raise SessionStateError(
            f"运行状态 JSON 已损坏：{path}: {exc}"
        ) from exc
    if not isinstance(value, dict):
        raise SessionStateError(
            f"运行状态必须是 JSON 对象：{path}"
        )
    return value


def save_runtime_state(path: Path, value: dict) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    temporary = path.with_suffix(".tmp")
    temporary.write_text(
        json.dumps(value, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )
    temporary.replace(path)
```

在 Agent 中增加：

```python
def _save_runtime_state(self) -> None:
    state = load_runtime_state(
        self.session_workspace.state_file
    )
    state.update(
        {
            "version": 2,
            "session_id": self.session_workspace.session_id,
            "workspace": self.workspace_policy.to_dict(),
        }
    )
    save_runtime_state(
        self.session_workspace.state_file,
        state,
    )
```

Agent 创建完成后保存一次初始状态；每次授予外部目录访问后再次保存。后面加入 Mode、Budget、Plan 和已激活工具时继续更新同一个字典，不要覆盖 `workspace` 字段。

恢复时对所有路径重新执行 `resolve()`。目录已经不存在时从授权集合中移除；工作区根目录不存在时停止恢复并明确提示用户，不能悄悄退回当前目录。

安全边界如下：

```text
读取 workspace_root：直接允许
写入 workspace_root：仍经过现有编辑权限策略
首次读取外部目录：确认一次，本 Session 后续可读
首次写入外部目录：单独确认，本 Session 后续可写
授权整个磁盘或用户主目录：拒绝
Shell 访问外部路径：本功能不自动放行，仍需独立沙箱策略
```

```python
resolved_permission_mode = (
    args.permission_mode
    or runtime_state.get("permission_mode")
    or "default"
)
```

Budget Limits 也按同样方式逐项解析，不能因为用户只覆盖 `--max-turns`，就把 Session 中保存的价格和 `max_cost` 全部丢掉。

Agent 创建、加载消息和恢复状态的顺序是：

```text
定位 workspace_root
→ 读取 state.json
→ 解析 CLI 覆盖值
→ 创建 Agent
→ load_history(messages)
→ restore_runtime_state(state)
→ 如果本次显式传入 --plan，再调用 enter_plan_mode()
→ 保存一次合并后的最新状态
```

每轮对话结束、Plan 状态变化、Deferred Tool 激活、目录授权变化和退出程序时都调用 `_save_runtime_state()`。消息继续由 `save_session()` 保存，不能把 messages 再复制一份到 `state.json`。

旧版本迁移只负责补默认字段：

```python
def migrate_runtime_state(value: dict) -> dict:
    version = int(value.get("version", 1))
    if version == 1:
        migrated = dict(value)
        migrated["version"] = 2
        migrated.setdefault("workspace", {})
        migrated.setdefault("activated_tools", [])
        migrated.setdefault("budget_limits", {})
        migrated.setdefault("budget_usage", {})
        migrated.setdefault("plan", {})
        migrated.setdefault("last_usage", {})
        return migrated
    if version == 2:
        return value
    raise RuntimeError(f"无法迁移 Session 版本：{version}")
```

读取后立即迁移，不要在 JSON 损坏时静默恢复成空状态：

```python
try:
    runtime_state = migrate_runtime_state(
        load_runtime_state(workspace.state_file)
    )
except SessionStateError as exc:
    raise RuntimeError(
        f"会话 {session_id} 无法安全恢复：{exc}"
    ) from exc
```

文件不存在表示第一次启动，可以返回空字典；文件存在但损坏则是异常。两种情况不能混在一起，否则用户会看到“已恢复 0 条消息”，随后新状态又覆盖原文件。

### 13.15.10 让 Ctrl+C 真正取消当前任务

当前 `Agent` 已经有 `threading.Event()`，调度器也会在工具开始前检查它，但这还不是完整取消：模型流式响应没有检查事件，`run_shell` 进入 `subprocess.run()` 后也无法提前退出，`main.py` 更没有把 Ctrl+C 转交给 Agent。

完整链路应为：

```text
用户第一次按 Ctrl+C
→ main.py 设置同一个 cancelled Event
→ streaming 停止继续收集模型输出
→ scheduler 不再启动尚未执行的工具
→ 正在运行的 shell 子进程被终止
→ Agent 保留已经完成的消息并保存 Session

用户在取消过程中再次按 Ctrl+C
→ 强制退出当前程序
```

#### 第一步：增加统一取消异常

新建 `mini_claude/cancellation.py`：

```python
import threading


class AgentCancelled(RuntimeError):
    pass


def raise_if_cancelled(cancelled: threading.Event) -> None:
    if cancelled.is_set():
        raise AgentCancelled("当前任务已取消")
```

`Event` 是跨模块共享的取消信号，`AgentCancelled` 用来退出当前轮 Agent Loop。不要把取消包装成普通工具错误继续发给模型，否则模型会再次规划和调用工具。

#### 第二步：流式读取时检查取消

给 `streaming.py` 的 `collect_stream()` 增加参数：

```python

        raise_if_cancelled(cancelled)
        # 后面保留现有 chunk、usage、content 和 tool_calls 解析代码
```

`agent.py` 中现有调用只补一个参数：

```python

    stream,
    on_text=self.print_smooth,

```

不要整体替换 `collect_stream()`，现有工具调用增量拼接逻辑继续保留。

#### 第三步：让工具获得同一个取消信号

#### 第四步：让 Shell 可以中途停止

`subprocess.run()` 只有超时后才返回，应把 `RunShellTool.run()` 中启动命令的部分改成 `Popen` 并短周期检查取消。先增加：


然后只替换原来的 `subprocess.run(...)` 和超时处理：

```python
process = subprocess.Popen(
    args["command"],
    shell=True,
    cwd=context.project_root,
    text=True,
    encoding="utf-8",
    errors="replace",
    stdout=subprocess.PIPE,
    stderr=subprocess.PIPE,
)
deadline = time.monotonic() + float(timeout)

while True:
    if context.cancelled.is_set():
        process.terminate()
        try:
            process.wait(timeout=2)
        except subprocess.TimeoutExpired:
            process.kill()
        raise AgentCancelled("Shell 命令已取消")

    remaining = deadline - time.monotonic()
    if remaining <= 0:
        process.kill()
        stdout, stderr = process.communicate()
        return (
            f"Error: command timed out after {timeout} seconds"
            f"\nStdout:\n{stdout}\nStderr:\n{stderr}"
        )

    try:
        stdout, stderr = process.communicate(
            timeout=min(0.2, remaining)
        )
        break
    except subprocess.TimeoutExpired:
        continue

returncode = process.returncode
```

后面的输出格式只需把 `completed.stdout`、`completed.stderr`、`completed.returncode` 分别换成 `stdout`、`stderr`、`returncode`。这一步只保证当前 Shell 进程可停止；将 Shell 放入操作系统级 Job Object 或沙箱属于第 16 章的进程隔离增强。

在 `_call_model_stream()` 创建流以后记录并在结束时清理：

```python
        self._save_runtime_state()
```

这里的 `_chat_loop()` 就是你当前 `chat()` 中已有的消息追加、模型调用、Budget 检查、工具调度和 Plan Review 流程。移动时不改变它们的先后顺序；这个拆分只是保证所有出口都经过 `finally`。

#### 第六步：main.py 接管 Ctrl+C

### 13.15.11 用 Slash Command Registry 统一命令

如果继续在 `run_repl()` 中叠加 `if line == "/history"`，会话、Mode、模型和压缩功能会逐渐失控。命令应先注册，再统一解析和显示帮助。

#### 第一步：建立命令注册表

新建 `mini_claude/commands.py`：

```python
from collections.abc import Callable
from dataclasses import dataclass
import shlex


CommandHandler = Callable[[list[str]], str | None]


def unquote(value: str) -> str:
    if (
        len(value) >= 2
        and value[0] == value[-1]
        and value[0] in {'"', "'"}
    ):
        return value[1:-1]
    return value


@dataclass(frozen=True)
class CommandSpec:
    name: str
    usage: str
    description: str
    handler: CommandHandler


class CommandRegistry:
    def __init__(self) -> None:
        self._commands: dict[str, CommandSpec] = {}

    def register(self, spec: CommandSpec) -> None:
        if not spec.name.startswith("/"):
            raise ValueError("命令名称必须以 / 开头")
        if spec.name in self._commands:
            raise ValueError(f"命令重复：{spec.name}")
        self._commands[spec.name] = spec

    def dispatch(self, line: str) -> tuple[bool, str | None]:
        try:
            parts = shlex.split(line, posix=False)
        except ValueError as exc:
            return True, f"命令参数无法解析：{exc}"
        parts = [unquote(part) for part in parts]
        if not parts or not parts[0].startswith("/"):
            return False, None

        spec = self._commands.get(parts[0].lower())
        if spec is None:
            return False, None
        return True, spec.handler(parts[1:])

    def help_text(self) -> str:
        rows = ["可用命令："]
        for spec in self._commands.values():
            rows.append(
                f"  {spec.usage:<28} {spec.description}"
            )
        return "\n".join(rows)
```

`posix=False` 可以避免 Windows 路径中的反斜杠被当成转义符。

#### 第二步：由 CLI 应用持有当前 Agent

命令注册表不应该自己读写 Session。`main.py` 增加一个薄的 `CliApplication`，负责当前会话生命周期：

```python
class CliApplication:
    def __init__(
        self,
        agent: MINI_CLUE_AGENT,

        open_session: Callable[
            [str | None, Path | None],
            tuple[MINI_CLUE_AGENT, str],
        ],
        list_sessions: Callable[[], list[dict]],
    ) -> None:
        self.agent = agent
        self.session_id = session_id
        self.open_session = open_session
        self.list_sessions = list_sessions
        self.running = True
        self._agent_closed = False
        self.commands = CommandRegistry()
        self._register_commands()
```

`open_session(session_id, cwd)` 复用 13.15.6 和 13.15.9 的统一启动流程：`session_id is None` 时创建会话，否则定位并恢复会话。不要在 `/resume` 中复制第二套恢复代码。

#### 第三步：注册第一批完整命令

在 `_register_commands()` 中集中描述：

```python
def _register_commands(self) -> None:
    specs = [
        ("/help", "/help", "显示所有命令", self._help),
        ("/status", "/status", "显示会话、Mode、模型和预算", self._status),
        ("/history", "/history", "显示对话角色和内容摘要", self._history),
        ("/sessions", "/sessions", "列出可恢复会话", self._sessions),
        ("/resume", "/resume <id>", "切换到已有会话", self._resume),
        ("/new", "/new [目录]", "创建并切换到新会话", self._new),
        ("/mode", "/mode <default|plan>", "切换运行模式", self._mode),
        ("/model", "/model [名称]", "查看或切换模型", self._model),
        ("/cwd", "/cwd", "显示当前会话工作区", self._cwd),
        ("/permissions", "/permissions", "显示目录和权限状态", self._permissions),
        ("/compact", "/compact", "立即压缩旧上下文", self._compact),
        ("/clear", "/clear", "清空当前会话消息", self._clear),
        ("/exit", "/exit", "保存并退出", self._exit),
    ]
    for name, usage, description, handler in specs:
        self.commands.register(
            CommandSpec(name, usage, description, handler)
        )
```

命令分为三类：

| 类型 | 命令 | 是否调用模型 |
|---|---|---|
| 查询 | `/help`、`/status`、`/history`、`/sessions`、`/cwd`、`/permissions` | 否 |
| 修改当前状态 | `/mode`、`/model`、`/compact`、`/clear` | 否 |
| 会话生命周期 | `/new`、`/resume`、`/exit` | 否 |

这些是应用控制命令，不能作为普通用户消息发给模型，也不应注册为 Tool。

#### 第四步：实现查询命令


#### 第五步：实现 Mode、Model、压缩和清空

```python
    save_session(
        self.agent.session_workspace,
        self.agent.history(),
    )
```

为避免命令层直接操作私有方法，Agent 同时补齐公开方法：

#### 第六步：实现会话切换

先统一保存和关闭当前会话：

```python

        return
    save_session(
        self.agent.session_workspace,
        self.agent.history(),
    )
    self.agent._save_runtime_state()
```

再实现 `/resume` 与 `/new`：

```python
def _resume(self, args: list[str]) -> str:
    if len(args) != 1:
        return "用法：/resume <session_id>"
    if args[0] == self.session_id:
        return "当前已经是该会话。"

    new_agent, new_id = self.open_session(args[0], None)
    self._close_current()
    self.agent = new_agent
    self.session_id = new_id
    self._agent_closed = False
    return (
        f"已恢复会话 {new_id}，"
        f"共 {len(new_agent.history())} 条消息。\n"
        f"{self.history_text()}"
    )


def _new(self, args: list[str]) -> str:
    if len(args) > 1:
        return "用法：/new [目录]"
    cwd = Path(args[0]).resolve() if args else self.agent.project_root
    new_agent, new_id = self.open_session(None, cwd)
    self._close_current()
    self.agent = new_agent
    self.session_id = new_id
    self._agent_closed = False
    return f"已创建会话 {new_id}，工作区：{cwd}"


def _exit(self, args: list[str]) -> str:
    self._close_current()
    self.running = False
    return "会话已保存。"
```

一定先成功打开目标会话，再关闭当前会话。这样目标 Session 损坏时，用户仍留在当前可用会话中。`open_session()` 还必须验证 Session Index、`state.json` 和消息文件中的 `session_id` 一致，不能恢复出 0 条消息后静默创建新 ID。

### 13.15.12 收拢最终 REPL 流程

先把原来散落在 `main()` 中的新建与恢复逻辑提取成唯一入口。下面的 `first_value()` 保留 `0.0`，不能用连续 `or` 解析价格：

```python
def first_value(*values):
    for value in values:
        if value is not None:
            return value
    return None


def open_session(
    session_id: str | None,
    cwd: Path | None,
    args: argparse.Namespace,
    *,
    enter_plan: bool = False,
) -> tuple[MINI_CLUE_AGENT, str]:
    restoring = session_id is not None

    if restoring:
        root = find_session_root(session_id)
        if root is None:
            raise RuntimeError(
                f"找不到会话 {session_id!r} 对应的工作区"
            )
        if cwd is not None and cwd.resolve() != root:
            raise RuntimeError(
                "恢复会话时 --cwd 与原工作区不一致"
            )
    else:
        session_id = uuid4().hex
        root = (cwd or Path.cwd()).resolve()
        if not root.is_dir():
            raise RuntimeError(f"工作区不存在：{root}")

    workspace = create_session_workspace(root, session_id)
    state = migrate_runtime_state(
        load_runtime_state(workspace.state_file)
    )

    saved_id = state.get("session_id")
    if saved_id is not None and saved_id != session_id:
        raise RuntimeError(
            "state.json 中的 session_id 与目录不一致"
        )

    workspace_value = state.get("workspace")
    if (
        isinstance(workspace_value, dict)
        and workspace_value.get("workspace_root")
    ):
        policy = WorkspacePolicy.from_dict(workspace_value)
        if policy.workspace_root != root:
            raise RuntimeError(
                "Session Index 与 state.json 的工作区不一致"
            )
    else:
        policy = WorkspacePolicy(root)

    limits = dict(state.get("budget_limits", {}))
    resolved_model = first_value(
        args.model,
        state.get("model"),
        None,
    )
    resolved_api_base = first_value(
        args.api_base,
        state.get("api_base"),
        None,
    )
    resolved_permission = first_value(
        args.permission_mode,
        state.get("permission_mode"),
        "default",
    )
    resolved_mcp_config = resolve_mcp_config_path(
        args.mcp_config,
        state.get("mcp_config_path"),
        root,
    )

    agent = MINI_CLUE_AGENT(
        session_id=session_id,
        project_root=root,
        workspace_policy=policy,
        permission_mode=resolved_permission,
        model=resolved_model,
        api_base=resolved_api_base,
        max_turns=first_value(
            args.max_turns,
            limits.get("max_turns"),
        ),
        max_cost_usd=first_value(
            args.max_cost,
            limits.get("max_cost_usd"),
        ),
        input_price_per_million=first_value(
            args.input_price,
            limits.get("input_price_per_million"),
            0.0,
        ),
        output_price_per_million=first_value(
            args.output_price,
            limits.get("output_price_per_million"),
            0.0,
        ),
        cache_read_price_per_million=first_value(
            args.cache_read_price,
            limits.get("cache_read_price_per_million"),
            0.0,
        ),
        mcp_manager=(
            McpManager.from_config(resolved_mcp_config)
            if resolved_mcp_config is not None
            else McpManager()
        ),
        mcp_config_path=resolved_mcp_config,
    )

    if restoring:
        agent.load_history(load_session(workspace))
        agent.restore_runtime_state(state)
    if enter_plan:
        agent.enter_plan_mode()

    agent._save_runtime_state()
    if not restoring:
        register_session(session_id, root)
    return agent, session_id
```

`resolve_mcp_config_path()` 按 13.15.13 的“CLI → Session → 环境变量”顺序返回 `Path | None`。`open_session()` 成功创建 Agent 后才登记新会话，避免配置错误时在全局索引留下无法打开的空 Session。

创建 `CliApplication` 时用闭包固定本次 CLI 覆盖值，但 `/new` 和 `/resume` 不重复应用启动时的 `--plan`：

```python
initial_agent, initial_id = open_session(
    args.resume,
    args.cwd,
    args,
    enter_plan=args.plan,
)
app = CliApplication(
    initial_agent,
    initial_id,
    open_session=lambda session_id, cwd: open_session(
        session_id,
        cwd,
        args,
        enter_plan=False,
    ),
    list_sessions=list_session_entries,
)
if args.resume:
    print(
        f"已恢复 {len(app.agent.history())} 条消息。\n"
        f"{app.history_text()}"
    )
```

注册表完成后，`run_repl()` 只负责输入、分流、保存和显示，不再理解每个命令的细节：

```python
def run_repl(app: CliApplication) -> None:
    print("mini-agent：输入任务，/help 查看命令。")
    while app.running:
        try:
            line = input("你：").strip()
        except KeyboardInterrupt:
            print("\n当前没有运行任务，输入 /exit 退出。")
            continue

        if not line:
            continue

        handled, output = app.commands.dispatch(line)
        if handled:
            if output:
                print(output)
            continue

        expanded = resolve_skill(
            line,
            app.agent.tool_context.project_root,
        )
        if line.startswith("/") and expanded is None:
            print(
                f"未知命令或 Skill：{line.split()[0]}，"
                "输入 /help 查看内置命令。"
            )
            continue
        user_text = expanded or line
        try:
            app.agent.chat(user_text)
        finally:
            save_session(
                app.agent.session_workspace,
                app.agent.history(),
            )
            app.agent._save_runtime_state()
        show_cache(app.agent)
```

`main()` 的最终职责顺序为：

```text
parse_args()
→ open_session(args.resume, args.cwd, CLI 覆盖参数)
→ 创建 CliApplication
→ 注册以 app.agent 为动态目标的 Ctrl+C handler
→ 有位置参数 prompt：执行一次并保存
→ 否则进入 run_repl(app)
→ finally 中再次保存并 close（允许重复调用）
```

安装中断处理器时使用：

```python
install_interrupt_handler(lambda: app.agent)
```

不要使用 `lambda: agent`，否则 `/resume` 切换以后 Ctrl+C 仍会取消旧 Agent。

最后把单次任务和 REPL 接到同一个应用生命周期上：

```python
install_interrupt_handler(lambda: app.agent)
prompt = " ".join(args.prompt).strip()

try:
    if prompt:
        app.agent.chat(
            resolve_user_input(app.agent, prompt)
        )
        show_cache(app.agent)
    else:
        run_repl(app)
finally:
    app._close_current()
```

`_close_current()` 已通过 `_agent_closed` 保证幂等，因此 `/exit` 已经关闭过一次时，`finally` 不会重复保存或再次关闭 MCP 进程。

内置 Slash Command 应在 Skill 解析前处理。用户输入 `/help` 绝不能再进入 `resolve_skill()`；注册表找不到 `/commit` 等名称时，再尝试现有 Skill。两边都找不到才显示“未知命令或 Skill”，不能把未知斜杠命令直接发给模型。

### 13.15.13 MCP 配置如何进入完整启动流程

`--mcp-config` 不直接创建一个新的 MCP 客户端实现，而是把配置路径交给 13.14 已完成的 `McpManager`：

```python
import os


def resolve_mcp_config_path(
    cli_value: Path | None,
    state_value: str | None,
    workspace_root: Path,
) -> Path | None:
    raw = (
        cli_value
        or state_value
        or os.environ.get("MINI_MCP_CONFIG")
    )
    if raw is None:
        return None
    path = Path(raw)
    if not path.is_absolute():
        path = workspace_root / path
    resolved = path.resolve()
    if not resolved.is_file():
        raise RuntimeError(
            f"MCP 配置文件不存在：{resolved}"
        )
    return resolved


resolved_mcp_config = resolve_mcp_config_path(
    args.mcp_config,
    runtime_state.get("mcp_config_path"),
    workspace_root,
)

mcp_manager = (
    McpManager.from_config(resolved_mcp_config)
    if resolved_mcp_config is not None
    else McpManager()
)
agent = MINI_CLUE_AGENT(
    # 保留其他参数
    mcp_manager=mcp_manager,
    mcp_config_path=resolved_mcp_config,
)
```

`state.json` 只保存配置文件路径：

```json
{
  "mcp_config_path": "E:\\projects\\demo\\.mini-agent\\mcp.json"
}
```

Token 仍放在环境变量中。恢复 Session 时重新启动配置中的 MCP Server；某个 Server 连接失败只标记该 Server 不可用，并显示原因，不能让本地文件工具一起启动失败。

### 13.15.14 本节验证

按下面顺序验证，不要只检查“程序能启动”：

1. **参数组合**：`--resume <id> --plan` 能同时生效；`--new --resume <id>` 被 argparse 拒绝。
2. **工作区**：`--new --cwd <path>` 后，Session Index 和 `state.json` 都记录同一绝对路径。
3. **恢复**：退出后用 `/resume <id>` 恢复，消息数、Mode、模型、Budget、目录授权和 Deferred Tool 激活状态不变。
4. **损坏状态**：故意破坏副本中的 `state.json`，程序明确报告损坏且不覆盖原文件。
5. **命令发现**：`/help` 显示全部注册命令；`/commit` 等已有 Skill 仍能执行；未知 `/abc` 只提示未知命令或 Skill，不进入模型。
6. **会话切换**：`/new` 创建新 ID；`/resume` 返回旧 ID；继续对话仍写入旧 Session 目录。
7. **手动压缩**：`/compact` 复用原摘要逻辑，消息角色和 `tool_call_id` 配对仍合法。
8. **模型取消**：模型流式输出时按一次 Ctrl+C，本轮停止但 REPL 仍可继续输入。
9. **工具取消**：执行长时间 Shell 后按 Ctrl+C，子进程退出，未开始的并行工具不再启动。
10. **强制退出**：取消过程中再次 Ctrl+C，程序退出；下次恢复能看到取消前完整保存的历史。
11. **MCP 隔离**：MCP 配置错误时显示该 Server 的失败原因，本地 `read_file` 仍能使用。
12. **单次模式**：带位置参数运行结束后，messages 和 `state.json` 都保存一次，不额外创建新 Session。

完成后，第 13 章得到的是单进程但闭环的 Mini Claude：参数可配置、会话可发现和切换、每个会话拥有独立工作区、运行状态可恢复、任务可取消、命令可发现。Daemon、TUI、多客户端共享状态和真正的操作系统级进程沙箱留到第 16 章，不在这里提前混入。
