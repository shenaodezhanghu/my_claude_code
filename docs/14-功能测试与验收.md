# 第十四章 功能测试与验收

> 本章对应原版 `docs/14-testing.md`。它不新增 Agent 能力，只验证第零章到第十二章已经完成的功能。第十五章的自治功能必须等实现后再测试，不能提前混入当前代码。

## 14.1 为什么 Agent 需要两类测试

普通函数适合自动化测试，例如权限结果、路径限制和 Skill 解析；模型是否正确选择工具具有不确定性，更适合端到端场景测试。

```text
单元测试
→ 验证确定性 Python 逻辑

场景测试
→ 验证模型、工具、权限和历史能否形成闭环
```

## 14.2 测试前准备

确认 Working Directory 是：

```text
myclaude/myclaude
```

恢复正式阈值：

```python
LARGE_RESULT_BYTES = 30 * 1024
COMPACT_TRIGGER_CHARS = 80_000
```

确认 `.env` 中存在百炼配置，但不要把 Key 提交到 Git：

```env
OPENAI_API_KEY=你的百炼Key
OPENAI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
MINI_CLAUDE_MODEL=qwen-plus
```

## 14.3 Phase 1：模型与基础 Agent Loop

### Test 1：普通对话

```bat
python main.py "只回复 hello"
```

预期：流式输出一次，不出现重复回答，也不调用工具。

### Test 2：读取文件并回答

```text
读取 AGENTS.md，概括其中最重要的三条规则。
```

预期：出现一次或多次 `read_file`，随后模型依据真实内容回答。

### Test 3：不存在的工具和错误参数

通过单元测试直接执行：

```python
result = registry.execute("missing_tool", {}, context)
assert "unknown tool" in result.lower()
```

工具错误应作为字符串返回，不应让 Agent Loop 崩溃。

## 14.4 Phase 2：文件、搜索和 Shell

### Test 4：文件定位

```text
在整个项目中搜索名为 memory.py 的文件，只报告路径。
```

预期：使用 `list_files`，不会只检查项目根目录。

### Test 5：Grep Search

```text
搜索项目中所有调用 check_permission 的位置。
```

预期：返回文件路径和匹配行，不使用 Shell 替代已有 `grep_search`。

### Test 6：Write File 与目录创建

```text
在 notes/test.txt 写入 hello。
```

预期：默认权限模式先询问；同意后自动创建 `notes/` 并写入文件。

### Test 7：Read-before-edit

先让 Agent 编辑一个从未读取的现有文件。预期工具拒绝并提示先读取；读取后再次编辑应成功。

### Test 8：危险 Shell

```text
运行 git reset --hard
```

预期：必须确认或拒绝，不能直接执行。测试时选择 `N`，不要真的运行破坏性命令。

## 14.5 Phase 3：流式、重试和大结果

### Test 9：流式工具调用重建

要求模型读取文件并总结。确认工具名和 JSON 参数即使分片返回，也能被完整组装。

### Test 10：大结果持久化

准备一个超过 30 KB 的文本文件并读取。确认：

- `.mini-agent/tool-results/` 保存完整内容。
- `messages` 中只有预览和相对路径。
- 再次读取结果文件不会丢失原始内容。

### Test 11：上下文压缩

仅测试时把阈值临时改为 2,000，进行多轮对话，确认出现压缩提示且没有 `tool_call_id` 错误。完成后必须恢复 80,000，避免每轮工具调用都压缩。

## 14.6 Phase 4：Session、Memory 和 Skills

### Test 12：Session Resume

记录会话 ID，退出后运行：

```bat
python main.py --resume <session-id>
```

预期：恢复消息数量并显示历史；继续对话时仍能使用此前信息。

### Test 13：跨会话 Memory

在 `.mini-memory/deployment.md` 写入测试部署约定，启动新会话后询问相关问题。预期相关记忆进入 System Prompt；无关问题不应召回。

### Test 14：Skill

```text
/commit 重点说明权限系统
```

预期：`.mini-skills/commit.md` 正文与参数一起进入 `agent.chat()`；`/clear` 仍优先作为内置命令处理。

## 14.7 Phase 5：Plan Mode、子 Agent 和 MCP

### Test 15：Plan Mode

```bat
python main.py --plan "在 notes/plan.txt 写入计划"
```

预期：可以读取和搜索，但 `write_file` 直接 deny，不出现 `[y/N]`。

### Test 16：只读子 Agent

```text
使用子 Agent 调查权限系统，只返回结论和关键文件。
```

预期：主历史只保存 `agent` 工具任务和总结；子 Agent 只能看到三个只读工具。

### Test 17：MCP

```bat
set "MINI_MCP_SERVER=..\..\steps\mcp-demo-server.mjs"
python main.py "使用 add 工具计算 17 + 25"
```

预期：发现 `mcp__demo__add`，确认调用后返回 `42`，程序退出时关闭子进程。

## 14.8 建立最小自动化测试目录

推荐结构：

```text
tests/
├── test_context.py
├── test_memory.py
├── test_permissions.py
├── test_registry.py
├── test_session.py
└── test_skills.py
```

优先测试不依赖真实模型的纯函数：

```python
def test_plan_mode_denies_write():
    result = check_permission(
        "write_file",
        {"path": "demo.txt"},
        mode="default",
        agent_mode="plan",
    )
    assert result.action == "deny"
```

运行：

```bat
pip install pytest
pytest -q
```

模型端到端测试应使用假的客户端或固定响应，避免每次运行都产生费用和不确定输出。
